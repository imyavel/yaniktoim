# batch_runner — простой батч-раннер трансформации

Запускает `src/3_transform.py` партиями по N статей. После каждой
успешной партии — рендер + пересборка индексов + (опц.) `git push`.
На «hit your limit» от Claude — парсит время сброса, спит до него,
повторяет ту же партию.

Без чанкования, без Telegram, без параллелизма. Идея — последовательно
прогнать все 350 статей за несколько суток, разрывая на лимитах.

## Запуск (из корня yaniktoim/)

```bash
# дотрансформировать ВСЁ что осталось
python batch_runner/run_batch.py

# только из раздела «Избранное»
python batch_runner/run_batch.py --section best

# первые 20 статей текущей очереди
python batch_runner/run_batch.py --limit 20

# показать очередь, ничего не запускать
python batch_runner/run_batch.py --dry-run

# не пушить в gh-pages после каждой партии
python batch_runner/run_batch.py --no-push

# другая размерность партии (по умолчанию 5)
python batch_runner/run_batch.py --batch-size 3
```

Очередь = все статьи из `manifest.json` (с учётом фильтра `--section`),
для которых ещё нет `json/<NNN>.json`. То есть прерванный прогон
продолжается с того же места: source of truth — файловая система,
а не state.json.

## GUI (двойной клик)

`batch_runner/gui.pyw` — Tk-окно поверх `run_batch.py` (по образцу `ZoharTGBatch/gui.pyw`):
- Сверху — выбор раздела, лимит, размер пачки, чекбокс `--no-push`.
- Кнопка `Dry-run` — увидеть очередь без запуска.
- `Start` / `Stop` — Stop отправляет Ctrl-Break (graceful), потом kill через 30 сек.
- В большом тёмном логе — stdout/stderr субпроцесса в реальном времени.
- Внизу — счётчик очереди (всего / трансформировано / осталось).
- На каждый день: `gui_YYMMDD.log` рядом со скриптом (append-only).

Запуск двойным кликом — pythonw.exe (без чёрной консоли).

## Файлы

- `run_batch.py` — собственно раннер (CLI)
- `gui.pyw` — Tk-обёртка
- `state.json` — список `done` / `failed` (вспомогательно, для статистики)
- `batch.log` — append-only лог CLI-запусков
- `gui_YYMMDD.log` — лог GUI за день

## Поведение при сбоях

| Симптом в stdout/stderr | Действие |
|---|---|
| `hit your limit` + `resets HH:MM` | спим до этого времени + 60s, повторяем тот же батч |
| `hit your limit` без времени | спим 5 ч, повторяем |
| `401` / `403` / `invalid api key` / `quota exhausted` | FATAL, выходим (надо разбираться вручную) |
| `claude exit ≠ 0` без признаков лимита | заносим в `failed`, идём дальше |
| Ctrl+C | сохраняется state, можно перезапустить — продолжит |

## Что НЕ делает

- Не запускает несколько `claude.exe` в параллель.
- Не делит длинные статьи на части (в transform_prompt.md одна статья = один промпт).
- Не редактирует уже существующие `json/<NNN>.json`.

Когда дойдём до места, где это надо — допишем.
