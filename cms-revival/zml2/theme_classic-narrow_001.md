# Theme-Spec — `classic-narrow` (v001)

> Источник: `variant_classic/index.html` + `variant_classic/run.log`.
> Все значения извлечены ФАКТически из `<style>` макета. Документ самодостаточен:
> по нему стиль воссоздаётся с нуля, без исходного HTML.
> **Важно про единицы:** `html` не задаёт `font-size`, поэтому `1rem = 16px` (корень),
> при этом `body { font-size: 21px }` задан в пикселях. То есть базовый текст набран 21px,
> а вся rem-шкала отсчитывается от 16px. Это расхождение зафиксировано и скорректировано в §3.

---

## 1. Идентичность темы

- **Имя:** `classic-narrow` (Classic, узкий вариант).
- **Эстетика:** классическая книжная типографика с засечками — «старинное богослужебно-философское издание». Антиква, рубрикация красным (оксид/киноварь), буквица, флероны-разделители, симметрия по центральной оси, бумажно-светлый фон.
- **Общее впечатление:** разворот старой печатной книги / титульный аппарат + научный аппарат сносок. Тёплая бумага, оттиснутый лист, ручная пунктуация.
- **Контейнер / ширина:**
  - Внешний отступ страницы: `.page { padding: clamp(1rem, 4vw, 4rem) 1rem }`.
  - «Лист» (`.sheet`): `max-width: 50rem` (=800px), центрирован, фон `--sheet`, рамка `1px solid --rule`, многослойная тень оттиска:
    `0 1px 0 #fff inset, 0 18px 50px -28px rgba(60,44,20,.55), 0 4px 14px -10px rgba(60,44,20,.35)`.
    Внутр. паддинг листа: `clamp(1.6rem, 5vw, 5.5rem) clamp(1.2rem, 5vw, 5rem)`.
  - **Колонка набора** (`.inner`): `max-width: var(--maxw) = 42rem` (=672px) — это и есть «узкая» мера.
- **Сетка:** одноколоночная, всё центрировано по оси. Вложенные блоки имеют собственные суженные меры:
  эпиграфы `max-width: 34rem`, молитва `36rem`, стих — `width: fit-content` (по самой длинной строке).

- Тема почти без скруглений (книжная строгость). Единственные радиусы:

- Между секциями — флероны-разделители `margin: 2.7rem auto`.
- Эпиграф: `margin: 2.4rem 0`; глава: `margin-top: 3.4rem`; сноски: `margin-top: 3rem`.
- Абзац прозы: `margin-bottom: 1.2rem`; строфа: `margin-bottom: 1.5rem`.

**Ограничения и диагноз.**

- Минимум 11.8px (kicker) и 12.8px (cert) **ниже читаемого порога** для длинного чтения; заголовок 52.8px — в пределах разумного потолка.
- Несогласованность баз: body 21px ↔ rem-шкала от 16px (kicker «кажется» ещё мельче относительно текста).

### СКОРРЕКТИРОВАННАЯ шкала (рекомендуется к воссозданию)
Привести `html { font-size: 16px }` и измерять всё в rem от единой базы; зажать минимум ≥ **13px**, потолок ≤ **52px**, отношение **≤ 4.0×**.

| Роль | Было | **Стало** |
|---|---|---|
| Главный заголовок | `clamp(2rem,6vw,3.3rem)` | `clamp(2rem, 6vw, 3.25rem)` (≤52px) |
| Титул главы | `clamp(1.7rem,4.6vw,2.4rem)` | без изменений |
| body | `21px` | `1.3125rem` (=21px, но в rem от 16px) |
| Тело сносок `.fn-list` | `.92rem` (14.7) | `.875rem` ≥14px — ок, оставить |
| Колофон | `.86rem` | `.875rem` (14px) |
| `.cert` | `.8rem` (12.8) | **`.8125rem` (13px)** — поднять до пола |
| `.kicker` | `.74rem` (11.8) | **`.8125rem` (13px)** + сохранить `letter-spacing:.32em` |

Итог: мин 13px, макс 52px → **отношение 4.0×** (вместо 4.5×). Капительные строки (kicker, label) держим у пола 13px и компенсируем читаемость разрядкой, а не размером.

## 5. Модель стиха

- **Одноколоночная.** `.verse { width: fit-content; max-width: 100%; margin: 1.9rem auto; text-align: left }` — блок ужимается по самой длинной строке и центрируется как объект, но строки выровнены влево.
- **Стрелки-коннекторы между колонками НЕ нужны** (нет двухколоночной раскладки → нет «перетекания» строк между колонками).
- **Разбивка на строфы:** каждая `<p class="stanza">` = строфа (`margin-bottom 1.5rem`, `line-height 1.85`; в `.verse.long` — `1.78`). Внутри строфы каждая строка — `<span class="line">` с **висячим отступом** для переноса: `padding-left:1.4em; text-indent:-1.4em` (перенос длинной строки выравнивается под началом первой).
- **Авторская сегментация:** двойной пробел в источнике = граница строфы (катрены в гл. I–II, длинный непрерывный «поток-молитва» в гл. III как одна большая строфа).
- Стих-эпиграф внутри главы (диалог из «Аватара») — отдельный `blockquote.epi-verse` с инлайн-сужением `max-width:30rem`, курсив, центр.

## 6. Сноски

- **Модель:** надстрочные якоря в тексте + концевой нумерованный список («Полезные ссылки»).
  - Якорь: `<sup class="fnref"><a id="refN" href="#fnN">N</a></sup>`.
  - Список: `<ol class="fn-list"><li class="fn-item" id="fnN">…<a class="backref" href="#refN">↩</a></li></ol>`.
- **Навигация туда-обратно:** вперёд — клик по `refN`→`#fnN`; назад — стрелка `↩` (`.backref`, `--rubric`) `fnN`→`#refN`. (Из 30 целей 26 имеют двусторонние ссылки; 4 несослыланные в оригинале — №4, 6, 10, 28 — оставлены БЕЗ `↩`, по run.log.)
- **Вёрстка элемента:** `.fn-item { position:relative; padding:.55rem 0 .55rem 2.6rem; border-top:1px solid --rule-soft; hyphens:auto }`, последний — ещё `border-bottom`. Номер `.fn-num` — абсолютно слева (`width 2.1rem; text-align:right`), Playfair `600`, `--rubric`, `.95rem`.
- **Заголовок раздела** `.footnotes h2` — Playfair `600`, `1rem`, капс, `letter-spacing .26em`, `--rubric`, центр.
- **Внутренние элементы сноски:** разделитель `.sep` (`::`) — `--ink-faint`; автор `.author` — курсив `--ink-faint`; источник-URL `.src` — `--gold` с `border-bottom:1px dotted --gold` (`:hover`→`--rubric`); сложные сноски с вложенным списком `.fn-sub` (маркер `.k` — `--rubric` `600`); «большие» сноски `.fn-item.grand .lede` — курсив `--ink-faint`.
- **BASELINE-ТРЕБОВАНИЕ (замечание ревью #3) — подсветка активной цели `:target`:**
  ```css
  .fn-item:target{
    background:#fbeede;
    border-radius:.3rem;
    box-shadow:0 0 0 .5rem #fbeede;
  }
  ```
  Активная сноска заливается тёплым кремово-розовым `#fbeede`, со скруглением `.3rem` и «ореолом» `box-shadow` радиусом `.5rem` того же цвета (заливка визуально выходит за края текста, без резкой рамки). **Обязательно во всех темах.** (Рекомендация при воссоздании: добавить `scroll-margin-top` цели для удобной прокрутки.)

## 7. КАПС и глифы

- **КАПС — ЛИТЕРАЛЬНО как в источнике.** Без `text-transform`, без downcase, без `font-weight:bold`. Капс-пассаж (`.verse.majuscule`, от «ФОРМЕ ПОЛОВОГО ЧЛЕНА» до конца гл. II) и капс-эпиграф 2 (`.epi-prose`) набраны прописными ровно так, как в тексте.
- **Подача капс-крещендо:** не усилением (без болда/увеличения), а **обрамлением** — тонкие линейки сверху/снизу (`--rule-soft`), `padding 1.8rem 0`, лёгкая разрядка `letter-spacing .03em`, чуть уменьшённый кегль строк (`.97em`). Это читается как смена «голоса» на литургический/писанный, а не как крик.
- **Глифы/эмотиконы сохраняются ДОСЛОВНО** (как текст, не как декор):
  - `<\^/>` — в HTML экранирован (`&lt;\^/&gt;`); подан дважды (фронтиспис `--rubric-soft` + хвост заголовка `--rubric`).
  - `;::)))` — кода эпиграфа 1, отдельной строкой `.coda`, курсивом.
  - `;;;;` — сакральный рефрен-инвокация (`.sigil`): прямой шрифт, `--rubric`, `letter-spacing .1em`.
  - `;` и `^` — в финальных рефренах и скобочных строфах: `.sigil`, `--rubric`, `600`.
  - `::` — в сносках это авторский разделитель полей (`.sep`, `--ink-faint`), НЕ эмотикон.
- Принцип темы: глиф — это содержимое, тема лишь окрашивает/позиционирует его, никогда не заменяет картинкой и не нормализует пунктуацию.

## 8. Семантика vs оформление

### Чисто ОФОРМЛЕНИЕ (уходит в CSS-тему, данные не трогаем)
- Вся палитра, фон-градиенты, тени листа, рамка, радиусы.
- Шрифтовые пары EB Garamond / Playfair Display и feature-settings.
- Тип-скейл и вертикальный ритм (§3), скорректированная шкала.
- Центрирование, меры колонок (`42rem`/`34rem`/`36rem`), `text-wrap:balance`, justify+hyphens.
- Буквица (`::first-letter`), флероны-разделители и выбор символов-флеронов.
- Висячий отступ строк стиха, рамка капс-блока, разрядка.
- Цвет/вес глифов-сигилов; подсветка `:target` сносок; стиль стрелки `↩`.
- Капительная подача меток (kicker, epi-label, chapter-num) — это `text-transform`/`letter-spacing`, а не данные.

### Требует СЕМАНТИЧЕСКОГО различия в ДАННЫХ (для ZML 2)
- **Подтип эпиграфа.** Тема рисует три по-разному (`epi-verse` / `epi-prose` / `epi-aphorism`). Данные ДОЛЖНЫ нести подтип эпиграфа (стих / проза / афоризм) — иначе рендер не выберет трактовку.
- **Капс как смена голоса.** `verse.majuscule` — это не «текст оказался прописным», а семантический маркер «писание/литургический голос». Нужен флаг голоса/регистра в данных (литеральный КАПС сохраняется в контенте, но «это особый голос» — отдельный признак). НЕ выводить из самого факта прописных букв.
- **Нумерация/идентификатор главы.** Римская цифра-орнамент + «Стих первый/второй/третий» + титул — три отдельных поля (порядковый номер главы, словесная помета, заглавие). Номер не должен зашиваться в текст.
- **Модель сноски / тип цитаты.** Поля сноски структурны: вид («См. также» / «Музыка» / «Цитата из Х/Ф» / «без источника»), произведение, автор, URL-источник, вложенный список (ступени), «большая» сноска-молитва. Это данные, а не разметка. Также: факт «процитирована в тексте» vs «только в списке» (наличие двусторонней ссылки `↩`) — семантический признак (4/6/10/28 без обратной ссылки).
- **Жанр-помета прозаическая vs стиховая** (`.genre` vs `.genre.flow`) — курсив/прямой задаётся данными о типе пометы.
- **Рефрен-инвокация `;;;;`** как повторяющийся сакральный маркер — желательно семантический тип «рефрен», чтобы все темы узнавали его одинаково.
- **Сигилы/глифы** (`<\^/>`, `;`, `^`, `;::)))`) — часть контента; но «дублирование глифа как фронтисписа» — оформительское решение темы (фронтиспис генерится из того же значения, в данных он один раз).
- **Артикул и дата** — структурные поля выходных данных (не свободный текст kicker).
