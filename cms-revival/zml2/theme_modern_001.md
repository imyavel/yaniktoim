# Theme Spec — `modern_001` (Sacred-Modern Editorial / широкий)

Источник: `v2_modern/index.html` + `v2_modern/run.log`. Все значения извлечены фактически из CSS макета. Эта спека достаточна, чтобы воссоздать тему с нуля, не имея исходного HTML.

---

## 1. Идентичность темы

- **Имя:** `modern_001` — «Sacred-Modern Editorial».
- **Эстетика:** современный издательский разворот (журнал/арт-бук) на «бумажном» светлом фоне с одним уверенным сакральным акцентом — гранатово-красным. Контраст крупной дисплейной антиквы (Playfair Display) и сухого гротеска интерфейса (Manrope), на теле — мягкая антиква Spectral.
- **Общее впечатление:** монументально, но воздушно; богослужебно-поэтический текст подан как современная типографическая редактура, не как «древний свиток».
- **Контейнер/ширина:**
  - `--maxw: 1280px` — `.wrap{max-width:1280px;margin:0 auto;padding:0 clamp(20px,5vw,72px)}`.
  - Это **широкая** тема (отсюда «modern широкий»): полноширинные развороты и многоколоночные сетки внутри 1280px.
- **Сетка секции** (`.grid`): две колонки `minmax(190px,1fr) minmax(0,2fr)` → rail ≈ 1/3, main ≈ 2/3; `gap:clamp(2rem,5vw,5.5rem)`; `align-items:start`.
  - `rail.sticky` липкий на ширине ≥1024px: `position:sticky; top:36px`.
  - Брейкпоинт `max-width:860px`: всё схлопывается в одну колонку (`grid-template-columns:1fr`), rail становится статичным.

### Ограничения и КОРРЕКТИРОВКА
- **Потолок заголовка:** 96px (hero) приемлемо для широкой темы. Декоративная римская «I/II/III» (128px) — не текст-контент, а орнамент в rail; её разрешаем как исключение.
- **Минимум читаемости:** самый мелкий **текстовый** контент — сноски `0.96rem ≈ 15.4px`. Это на грани, но выше абсолютного минимума 14px. **Метки/эйбрау 11.5–12.5px** — это служебные капс-вразрядку лейблы, не сплошной текст, поэтому допустимы.
  - **Рекомендация (правка):** поднять `.masthead`/`.eyebrow` мин. размер с `0.72rem` до **`0.75rem` (12px)** ради WCAG-комфорта; оставить как опцию.
- **Отношение макс/мин (текстовый контент):** крупнейший текст 96px ÷ мельчайший текст 15.4px ≈ **6.2:1**. Это в разумных пределах для editorial-темы (потолок отношения держим ≤ **8:1**). Если декоративную римскую цифру считать частью шкалы — 128 ÷ 15.4 ≈ 8.3:1; держим её как орнамент вне текстовой шкалы, иначе отношение превышает лимит.
- **Вердикт:** дельта НЕ чрезмерна. Шкала принимается как есть, с единственной мягкой правкой минимума служебных лейблов до 12px.

## 5. Модель стиха

Тема использует **две модели в одной колонке** (main ≈ 2/3 ширины) — НЕ многоколоночный набор строф:

1. **Центрированные катрены** (`.verse.center`): стихи I и II. Каждая `.stanza` — блок строк `.line`, межстрофный отступ `clamp(1.8rem,3vw,2.8rem)`. Порядок чтения линеен сверху вниз.
2. **Epic / длинная строка** (`.verse.epic`): стих III. `text-align:left`, `max-width:none`, одна сплошная длинная строфа; буквица на первой строке (`.dropline::first-letter`: Playfair `800`, `--accent`, `1.6em`). `.stanza{padding-left:clamp(0px,2vw,1.6rem)}`.

**Регистровая драматургия** (важно): стих II начинается строчным регистром, затем переключается в КАПС-крещендо (`.stanza.caps`), затем — обрамлённый непрерывный `.surge` с молитвенной кодой. Это **семантическое** различие (см. §8), оформление лишь подаёт его.

### Стрелки-коннекторы (ревью #2)
В текущем макете порядок чтения **всегда однозначен** (одна колонка, линейно), поэтому коннекторы **не включаются**. Требование вступает в силу **условно**, если тема рендерит строфы в ≥2 колонки (что широкий контейнер 1280px допускает):

- **Логика включения:** коннекторы появляются ТОЛЬКО при многоколоночной раскладке строф, когда визуальный порядок (колонка → колонка, или змейкой) не очевиден. Управляется флагом темы `verse-columns ≥ 2`.
- **Вид:** лёгкая стрелка `→` (вниз-вправо для перехода между колонками) или `↘`, гротеск (`--grotesk`), цвет `--muted` (не акцент — коннектор служебный, не смысловой), `font-size:.8rem`, `opacity:.6`. Размещается в межколоночном жёлобе на стыке конца одной колонки и начала следующей, `aria-hidden="true"`.
- Между строфами одной колонки коннекторы НЕ ставятся (линейность очевидна).

## 6. Сноски

**Модель:** надстрочные якоря в тексте + концевой список карточек («Полезные ссылки / Аппарат»), двусторонняя навигация.

- **Маркер в тексте** (`sup.fn > a`): гротеск `700`, `font-size:.58em`, `vertical-align:super`, цвет `--accent`; `id="ref{N}"`, `href="#fn{N}"`. Hover → `--accent-deep`, без подчёркивания.
- **Раздел** (`.notes`): сетка `repeat(2,minmax(0,1fr))`, `gap:clamp(1.4rem,2.5vw,2.4rem) clamp(2rem,4vw,4rem)`. Открыт `.section-head` (эйбрау «Аппарат» + h2 «Полезные ссылки»).
- **Карточка** (`.note`, `id="fn{N}"`): сетка `auto 1fr`, `border-top:1px solid --line-soft`, `font-size:.96rem`, `line-height:1.62`, `--ink-soft`. Широкие сноски `.note--wide{grid-column:1/-1}`.
  - Номер `.note__num`: гротеск `800`, `.82rem`, `--accent`, формат `*N`.
  - Тело `.note__body`: `overflow-wrap:anywhere`; метка-тип `.src` (гротеск `600`, `--ink`, `.82rem`) напр. «См. также::», «Музыка::», «Цитата::»; ссылки `word-break:break-all`.
  - **Возврат** `.note__back`: `href="#ref{N}"`, символ `↩`, цвет `--muted`, `.85em` — навигация обратно к маркеру.
  - Подпункты `.note__sub` (для `*29`): `border-left:2px solid --line`, ключи `.k` (гротеск `700`, `--accent`, `.78rem`).

### BASELINE: подсветка активной сноски через `:target` (ревью #3)
В исходном макете **этого правила НЕТ** — его необходимо ДОБАВИТЬ (обязательно во всех темах). Спецификация для `modern_001`:

```css
.note:target{
  background:var(--accent-tint);              /* rgba(178,20,48,0.08) */
  border-top-color:var(--accent);             /* акцентная верхняя линия вместо line-soft */
  box-shadow:-3px 0 0 0 var(--accent);        /* акцентная вертикальная засечка слева */
  scroll-margin-top:48px;                      /* чтобы цель не липла к верху вьюпорта */
  transition:background .3s ease;
}
.note:target .note__num{color:var(--accent-deep);}
```
- Вид: при переходе по якорю `#fn{N}` целевая карточка получает мягкую гранатовую заливку (`--accent-tint`), акцентную верхнюю границу и вертикальную засечку слева — чётко выделяя «куда я перешёл». Симметрично можно подсветить и `sup.fn a:target` при возврате (опц.).

## 7. КАПС и глифы

- **КАПС литерально:** капс-пассажи приходят ЗАГЛАВНЫМИ из ДАННЫХ. CSS **не** применяет `text-transform:uppercase` к ним — наоборот, `.stanza.caps .line{text-transform:none}`. Никакого downcase, никакого `font-weight:bold` — лишь мягкая дифференциация: `letter-spacing:.04em`, `font-weight:500`. Это передаёт авторское крещендо, сохраняя текст дословно.
- **Глифы / эмотиконы — сохраняются дословно:**
  - `<\^/>` (в HTML как `&lt;\^/&gt;`) — авторская эмблема: в hero — капсула, в masthead/colophon/rule — акцентный инлайн `.mh-emblem`/`.glyph`.
  - `;;;;` — зачин-рефрен: `.refrain .glyph` / `.rule .glyph`, гротеск `800`, `--accent`.
  - `;` , `^` — точечные акценты: `.gl` и `.finale .g` (гротеск `700`, `--accent`, `font-style:normal`, `letter-spacing:-.02em`).
  - `::` — авторский разделитель внутри строк (`.gl`), сохранён (напр. «вместе::ведь», «См. также::»).
  - `;::)))` — эмотикон в хвосте эпиграфа I, сохранён в `.tail` цветом `--accent`.
- **Подача:** глифы подняты в акцентный цвет и гротеск как **смысловые** элементы авторского языка, не как декор. Регистр и пунктуация глифов никогда не нормализуются.

## 8. Семантика vs оформление

### Чисто CSS (уходит в тему, данные не меняются)
- Бумажная палитра, радиальные градиенты фона, `::selection`.
- Шрифтовые пары и весь тип-скейл (§3).
- Ширина 1280px, сетка rail/main 1:2, sticky-rail, брейкпоинт 860px.
- Капсула вокруг hero-глифа; буквицы (`::first-letter`); декоративные `.rule`-разделители.
- Акцентный цвет глифов, мягкий трекинг капс-строф, обрамление `.surge`.
- Подсветка `:target` сносок (§6) — чистый CSS, данных не требует.
- Декоративная римская цифра в rail (если номер главы есть в данных — см. ниже — рендер римской формы можно сделать на стороне темы из числа).

### Требует семантического различия в ДАННЫХ (для ZML 2)
- **Подтип эпиграфа:** «стих» (`.epi-verse`) vs «проза» (`.epi-prose`) vs «афоризм» (`.epi-strong`) — тема рисует их по-разному, но различие должно нести семантика блока (`epigraph.kind = verse|prose|aphorism`). Хвост-кода (`.tail`) и кода-строка `.katnut` — тоже семантические роли («атрибуция» / «терминологический акцент»).
- **Нумерация и прогресс главы:** «Стих первый» + «I — III» (порядковый номер + позиция в цикле из N) — данные должны нести `chapter.index`, `chapter.total`; римская форма выводится темой.
- **Регистровое крещендо:** переход строчный → КАПС → молитва — это не оформление, а структура. Данные должны помечать строфу как `stanza.role = normal|caps-crescendo|invocation` (а КАПС-текст хранится литерально заглавным). Тема НЕ имеет права угадывать крещендо.
- **Модель стиха блока:** `verse.layout = centered | epic-left` (и потенциально `columns:N`) — выбор раскладки и буквицы зависит от семантики, не от темы.
- **Модель сноски / тип источника:** метки `.src` («См. также», «Музыка», «Цитата», «без источника») — это `note.sourceType`, семантическое поле. Подпункты `*29` (`::1::`–`::4::`) — структурированный `note.subitems`. Связь маркер↔сноска (`ref{N}`/`fn{N}`) — семантические идентификаторы.
- **Врезка-эпиграф главы** (`.inline-epi`, диалог из «Аватара») — отдельный семантический блок «inline-epigraph/dialogue», отличный от обычного эпиграфа и от дескриптора.
- **Роль рефрена:** `;;;; Мужчиной и Женщиной Он создал Их` повторяется как лейтмотив — данные должны маркировать `refrain`, чтобы тема знала, что это повторяющийся зачин, а не обычная строка.
- **Глифы как контент:** `<\^/>`, `;;;;`, `;`, `^`, `::` — это контент-данные (авторский язык), а не декор темы; тема лишь стилизует их, но они присутствуют в источнике дословно.
