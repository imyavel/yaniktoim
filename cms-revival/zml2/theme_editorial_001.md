# Theme Spec — `editorial_001` (Editorial / широкий журнальный лонгрид)

> Источник: `v2_editorial/index.html`. Все значения извлечены из инлайн-CSS макета.
> Назначение: воспроизводимая спека темы для ZML 2. Тема описывает **только оформление**;
> семантические требования к данным вынесены в §8.

---

## 1. Идентичность темы

- **Имя:** `editorial_001` — «Editorial (широкий)».
- **Эстетика:** печатный журнал/арт-ревью на тёплой бумаге. Высокий контраст: акцидентный
  засечный титул + узкий гротеск-лейбл в разрядку + книжный засечный текст. Бордово-красный
  акцент, золото для глифов, чёрная типографика по кремовому фону.
- **Общее впечатление:** «лонгрид культурного издания» — крупные выворотные баннеры,
  многоколоночные потоки, аппарат сносок как энциклопедическая сетка.
- **Контейнер / ширина:**
  - `--maxw: 1480px`; обёртка `.wrap { width:92vw; max-width:var(--maxw); margin:0 auto; }`.
  - Это **широкая** тема: контентная мера тянется до 1480px, внутренние блоки сами задают
    более узкую меру через `max-width`/`ch` (см. ниже).
- **Сетка:** глобальной колоночной сетки нет; раскладка на CSS Grid/columns локально по блокам:
  - hero-bottom: `grid-template-columns: minmax(0,2fr) minmax(0,1fr)`;
  - эпиграфы (верхний ряд): `1.15fr 1fr`; feature-эпиграф: `minmax(0,2fr) minmax(0,1.05fr)`;
  - стихи: `repeat(auto-fit, minmax(255px,1fr))`;
  - молитва/финал: `columns:2`;
  - аппарат сносок: `repeat(auto-fill, minmax(330px,1fr))`.
- **Брейкпоинты:** `880px` (все 2-кол. → 1 кол.), `560px` (body 17px, verse/notes → 1 кол.,
  hero-title уменьшается до `clamp(2.2rem,12vw,3.4rem)`).

## 5. Модель стиха

**Многоколоночная** (это широкая тема — в этом её суть):
- катрены `.verse-grid` — авто-колонки `auto-fit minmax(255px,1fr)` (обычно 2–4 кол. при широком экране);
- финал `.finale` и часть молитвы — `columns:2`.

> **Ревью #2 — стрелки-коннекторы направления чтения (ОБЯЗАТЕЛЬНО для многоколоночных строф).**
> В исходнике их нет — это **добавление темы**. Логика: когда строфы/строки разложены в ≥2 колонки и
> порядок чтения не очевиден (особенно при `auto-fit`, где число колонок плавающее, и при `columns`,
> где поток идёт сверху-вниз левой колонки, затем правой), тема рисует лёгкие направляющие стрелки.
>
> **Вид:** тонкий знак `↳` / `→` (для перехода вправо к след. колонке) и `↩`/возврат вниз,
> `--label`, цвет `--gold`, `opacity:.55`, размер `~.8rem`, без фона. Размещение —
> через `::after` на последней `.stanza` колонки или абсолютный маркер в `column-gap`.
> **Логика включения:**
> - включать **только** когда фактических колонок ≥ 2 (через container query / JS-подсчёт или
>   медиазапрос > 880px);
> - на узком экране (`max-width:880px`, всё в 1 колонку) — **скрывать** (`display:none`);
> - в `columns`-потоке (молитва/финал) стрелка ставится у низа левой колонки → «продолжение справа сверху»;
> - в `auto-fit` сетке катренов, где строфы независимы и самодостаточны, стрелки факультативны —
>   включать только если данные помечают строфы как **непрерывный синтаксический поток** (см. §8),
>   иначе порядок строф не критичен и коннекторы не нужны.

## 6. Сноски

**Модель:** надстрочные якоря в тексте + концевой список-аппарат.
- Якорь `sup.ref a`: `id="ref-N"`, `href="#fn-N"`, цвет `--accent`, `--label` weight 600, `.56em`,
  `vertical-align:super`. Hover → `--accent-deep` + underline.
- Концевой раздел `.notes` с заголовком секции «Полезные ссылки». Сетка карточек
  `.notes-grid` = `auto-fill minmax(330px,1fr)`, `gap:1px`, фон `--line` (эффект «таблицы-решётки»).
- Карточка `.fn` (`id="fn-N"`): grid `auto 1fr`; крупный номер `.fn-num` (`--display` 800, `1.9rem`, `--accent`),
  тип `.fn-kind` (UPPERCASE label), заголовок `.fn-title`, автор `.fn-author` (italic, перед `· `),
  URL `.fn-url` (label, underline `--accent`), цитата `.fn-quote` (italic).
- «Тяжёлые» сноски `.fn-wide { grid-column:1/-1 }` (16 — цитата Зоар, 27 — термин, 28/29 — легенда
  глифа `;;;;` сеткой `.fn-legend` 1–4, 30 — молитва `columns:2`).

**Навигация туда-обратно:** прямой переход якорь→`#fn-N`; обратно — `.fn-back` («↩ к тексту»,
`href="#ref-N"`, `--label`, `--accent`). Сноски без обратной ссылки (4, 6, 10, 28) — это
**семантика данных** (нет якоря в тексте), а не оформление.

> **Ревью #3 — BASELINE: подсветка активной целевой сноски через `:target`.**
> В исходнике `:target` **отсутствует** — это **обязательное добавление темы** (во всех темах).
> Спецификация подсветки:
> ```css
> .fn:target {
>   background: var(--paper-2);                 /* фон-подложка вместо плоского --paper */
>   box-shadow: inset 3px 0 0 0 var(--accent);  /* левая акцентная линия */
>   animation: fnFlash 1.2s ease-out 1;         /* кратковременная вспышка */
> }
> @keyframes fnFlash { 0%{background:var(--paper-3);} 100%{background:var(--paper-2);} }
> /* зеркально для обратного перехода к якорю */
> sup.ref a:target, .fn-anchor:target { background: rgba(179,38,29,.18); border-radius:2px; }
> ```
> Линия `--accent` слева + тёплая подложка `--paper-2` однозначно выделяют целевую карточку
> в серой решётке аппарата.

## 7. КАПС и глифы

- **КАПС оставляем ЛИТЕРАЛЬНО** как в источнике: ни `text-transform` downcase, ни принудительного
  bold. В источнике капсовый пассаж в строфе задан инлайном
  `style="text-transform:uppercase;font-weight:600;color:var(--accent-deep)"` и капсовая молитва
  `fn-30` — это **контент**, тема его не модифицирует. UPPERCASE применяется темой только к
  служебным надписям (лейблы, титулы) — не к авторскому тексту.
- **Глифы/эмотиконы сохраняются дословно** (как текст, не как иконки):
  `<\^/>` (экран. `&lt;\^/&gt;`), `;::)))`, `;;;;`, `::`, `;`, `^`, `;;;;;;;;;`.
- **Подача глифов:** инлайн-класс `.glyph` — `--label`, weight 600, цвет `--gold`,
  `letter-spacing:.02em`; вариант `.glyph-accent { color:var(--accent) }`. В рефрене `.85em`,
  в мотиве `1.15em`. На тёмном баннере/легенде — `--gold-bright`. Глифы НЕ заменяются картинками,
  НЕ нормализуются — только перекрашиваются/масштабируются типографски.

## 8. Семантика vs оформление

### Чисто CSS (уходит в тему `editorial_001`)
- Шрифтовые пары, палитра, светлый бумажный фон с radial-gradient, `::selection`.
- Острые углы (нет радиусов), все линейки (2px/3px ink/accent), тёмный баннер feature-эпиграфа.
- Тип-скейл и его коррекция (§3); все `clamp`-отступы, меры `ch`/`max-width`.
- Раскладки: hero-grid, эпиграф-решётки, `columns:2` для молитвы/финала, `auto-fit` для катренов
  и `auto-fill` для аппарата сносок.
- Буквицы (`::first-letter`, `.dropcap`), watermark-кавычка, бейдж `.katnut`, разделители.
- Окраска/масштаб глифов (`.glyph`/`.glyph-accent`).
- **Стрелки-коннекторы (§5)** и **`:target`-подсветка сносок (§6)** — реализуются на CSS,
  но их *включение* зависит от семантических флагов (ниже).

### Требует семантического различия в ДАННЫХ (общий слой ZML 2)
1. **Подтип эпиграфа** — `verse` / `short` / `feature` (прозаический). Сейчас закодировано классами
   `epi-verse`/`epi-short`/`epi-feature`; данные должны нести этот атрибут, а не тема.
2. **Роль фрагмента**: lead-абзац, термин-бейдж «Катнут», кода эпиграфа, диалоговая реплика (`.dlg`).
3. **Нумерация/индекс главы** — «Стих первый/второй/третий» + порядок: это данные (счётчик/метка),
   тема лишь оформляет.
4. **Капс как контент vs капс как стиль** — авторский UPPERCASE-пассаж и крещендо должны быть
   помечены в данных как «эмоциональный пик / литеральный регистр», чтобы тема НЕ трогала регистр.
5. **Модель сноски / тип** — `fn-kind` («Музыка», «Цитата», «См. также», «Термин», «Легенда глифа»,
   пустая) — семантические категории; тема даёт им единый стиль.
6. **Наличие обратной ссылки** — сноски 4/6/10/28 без `↩` (нет якоря в тексте): это факт данных
   (упоминается/не упоминается), а не оформительское решение.
7. **`fn-wide` (полная ширина)** — следствие *объёма/типа* сноски (длинная статья, легенда, молитва);
   признак «тяжёлая сноска» должен приходить из данных, тема лишь растягивает `grid-column:1/-1`.
8. **Непрерывность строф** — флаг «строфы образуют единый синтаксический поток» (нужен для §5:
   когда включать стрелки-коннекторы между колонками, а когда строфы самодостаточны).
9. **Лейтмотивы** — повторяющиеся строки («Мужчиной и Женщиной Он создал Их», рефрен «Будущее за нами»,
   глиф `;;;;`) помечаются как лейтмотив в данных, чтобы тема давала им единый узнаваемый стиль.
