# ZML 2 — черновик формата (draft 002 — ворота 2b пройдены)

**Дата:** 2026-05-29
**Базис:** zml1 (`SPEC.md`) + дизайн-семантика 5 тем (стих + проза) + массовая корпус-семантика.
**Принцип:** единый семантический источник → N тем (различие тем ПРЕЗЕНТАЦИОННОЕ, в CSS).
В данные — только недеривируемая семантика, нужная ≥1 теме или корпусу.
**Терсность:** разметка на статью держится на уровне zml1; почти всё новое — *необязательные*
атрибуты и *редкие* блоки. Базовый средний документ (параграфы + `##` + `[^N]`/`[^N]:` + `[mus]`)
по объёму ≡ zml1.
**Статус 002:** все 16 пунктов реестра закрыты (`decisions_open_002.md`); ссылки `→ Q<n>` ниже
указывают на закрывший вердикт, не на открытый вопрос. Изменения vs draft 001: `[epil]` снят
(эпилог = `[epi]` в хвосте, Q3); inline-крючок `term/leitmotif` **активирован** опциональным
(Q13); политика orphan зафиксирована (Q11); добавлена §8 authoring-guidance (Q12/Q15).

## 1. Структура документа (унаследовано из zml1 без изменений)

```
---
<frontmatter — YAML, обязательный: title, art; опц. summary, date, image>
---

<intro-блоки до первой ##-секции>

## <Заголовок> {slug}
<блоки секции>

[^1]: <тело нумерованной сноски>
[^]:  <тело анонимной сноски>
```

Порядок жёсткий: frontmatter → intro → `##`-секции → блок сносок в самом конце.
art-id `XYZ[n]` (кодирует дату), `[[art]]`-цель, имя файла — **как в zml1 §2.3**.

### 1.1 Секция `##` — обобщена (опц. атрибуты)
```
## АКТ ПЕРВЫЙ {akt-1}                  ← как zml1
## Стих первый {s1} role=chapter        ← опц. role, когда не деривируется
```
- `{slug}` опц. (иначе `slugify`). CAPS→small-caps авто.
- `role=` **опционально**: `preface|epigraph|body|apparatus|colophon|prayer|chapter`.
  По умолчанию **деривируется** (preface = первая секция, apparatus = блок сносок,
  body = прочее). Текст кикера/eyebrow («Вступление») рендерит ТЕМА, не данные. → **Q5**
- `ord=` НЕ пишется: индекс/всего глав рендер считает по числу `role=chapter`. Форма
  (римская/арабская «Стих первый», «I — III») — CSS. → **Q5**

## 2. Блок-типы

Блоки разделяются пустой строкой. Сводка: что **унаследовано как есть**, что **обобщено**,
что **ново от дизайна**, что **зарезервировано (спит)**.

### 2.1 Унаследовано из zml1 как есть
| Тег | Семантика | Атрибуты |
|---|---|---|
| **параграф** (default) | базовый блок; подвиды attribution/colophon — авто | `dropcap` ДЕРИВ (→ Q6) |
| **`[poem]…[/poem]`** | стих: лесенка, авто-капитализация, CAPS-строфы→small-caps | `title=` опц. (→ Q4) |
| **`[sub]…[/sub]`** | подзаголовок-эхо H1 (часто с inline-сноской) | — |
| **`[mus]…[/mus]`** | музыка/медиа-группа; внутри `[url\|title\|author]` построчно | `[mus="label"]` опц. |

`[mus]` покрывает и «музыку в теле прозы», и «музыку-сноску» — **один тип, два места рендера**
(decision F). Поведение по URL (YouTube-плеер / flat / no-player) — как zml1 §4.8.

### 2.2 Обобщено (схождение стиха и прозы)
| Тег | Семантика | Что обобщено |
|---|---|---|
| **`[epi kind=verse\|prose\|aphorism]…[/epi]`** | эпиграф — рамочный мотто над текстом/разделом | + ось `kind` (все 5 тем рисуют 3 подтипа по-разному); `cite=` опц. — источник |
| **`[num]…[/num]`** | упорядоченный перечень N озаглавленных-номером единиц | один блок вместо «список аргументов» / «нумер. разделы» / «тезисы». Рендер сам ставит номера; форма (ol/section/rail-цифра) — CSS (decision C, → Q1) |

`[epi]` по умолчанию `kind=prose` (частый прозаический случай); `kind=verse` для стиховых
эпиграфов (как в zml1-демо), `kind=aphorism` для коротких сентенций (катнут).

**`[epi]` — функция, не цитатность (Q3).** Эпиграф определяется ролью *обрамления* (предваряет
или сопровождает содержание), а не «цитатностью»: содержимое — собственная проза/стих автора ИЛИ
внешняя цитата (тогда `cite=`). **Эпилог отдельным тегом НЕ вводится:** это `[epi]` в *хвостовой*
позиции документа — рендер деривирует позицию и при желании ставит метку «Эпилог». Это отличает
`[epi]` (обрамление) от `[quote]` (опора-цитата внутри тела) — различие по функции/позиции.

### 2.3 Активировано (спящие теги zml1 — корпус/проза доказали)
| Тег | Семантика | Обоснование |
|---|---|---|
| **`[quote kind=scripture]…[/quote]`** | **встроенная** цитата-источник В ПОТОКЕ (Писание) | НОВАЯ ось vs `[epi]`: эпиграф обрамляет, quote — опора внутри аргумента. 28/350 + prose 5/5. `cite=` обязателен по смыслу («— Ис. 6:2—3»). `kind` опц. (деф. `scripture`) (→ Q2) |

> **`[epil]` снят (Q3):** отдельный тег эпилога НЕ вводим. Эпилог = `[epi]` в хвостовой позиции
> (см. §2.2, функц. определение). Спящий `[epil]` из zml1 при миграции сворачивается в `[epi]`.
>
> Различие `[epi]` ↔ `[quote]` НЕ выводится из позиции (quote физически сидит ВНУТРИ
> раздела-эпиграфа — отметили classic/wide). Поэтому признак обязан быть в данных = разные теги.

### 2.4 Ново от дизайна
| Тег | Семантика | Обоснование |
|---|---|---|
| **`[sig]…[/sig]`** | подпись автора предисловия (правовыкл., курсив) | ≠ копирайт колофона (Зеир Арихович Анпин ≠ Элиягу Бар Малей); 5/5 вырезали из абзаца (decision D, → Q8) |
| **`[cry]…[/cry]`** | эмфатический возглас: рефрен / слоган / инвокация / closing | 5/5 финал-слоган + verse refrain/invocation/pledge — обобщены в один; КАПС литерально; стиль — CSS (decision I, → Q7) |

### 2.5 Зарезервировано (спит до первого появления)
| Тег | Семантика | Статус |
|---|---|---|
| **`[img src= alt=]` + подпись** | иллюстрация в теле | cover — в `frontmatter.image`; inline-`[img]` спит, активируем при первом реальном добавлении в тело (Q10, decided) |
| **`[dlg]…[/dlg]`** | диалог/реплики | спит; **проектируется и активируется на Фазе 4** на фикстуре `article3.txt` (форумная переписка читатель/автор) — ДО заморозки (Q9, decided) |
| **bulleted-список** | маркированный перечень | спит до реального кейса (ordered уже = `[num]`) (Q9, decided) |

## 3. Inline-конструкции (унаследовано из zml1 без изменений)

Порядок парсинга (как zml1 §7): `[^N]` → `[[art]]` → `{chapter|N}` → `[url|анкор]`
→ `_italic_` → CAPS-pass → `^WORD`.

| Конструкция | Семантика |
|---|---|
| **`[^N]`** | маркер сноски → sup + popup |
| **`[[art]]`** | внутр. ссылка; заголовок из manifest |
| **`{chapter\|N}`** | ссылка на Зоар; заголовок из zohar_index |
| **`[url\|анкор]` / `[url]`** | внешняя ссылка (голые URL запрещены, → Q14) |
| **`_фраза_`** | italic-эмфаза |
| **`^СЛОВО`** | заглавная внутри CAPS (Кли/Нагваль/Кетер) |

**Активирован опционально (Q13):** inline-крючок `term/leitmotif` — носитель пометки «осмысленный
термин/лейтмотив» в данных. Введён уже в v1, иначе понравившийся editorial-лейтмотив («Мужчиной и
Женщиной…») невоспроизводим из единого источника на Фазе 3. Опционален: тема, которой он не нужен,
его игнорирует (рендерит как обычный текст). **Кого метить — решает адаптирующая LLM по смыслу**,
статья за статьёй (см. §8). Синтаксис — финализируется на Фазе 3 при первом реальном применении
(кандидат: `{term|…}` либо `_=фраза=_`; выбрать минимально конфликтный с `_italic_`/`{chapter|N}`).

## 4. Сноски (тело — унаследовано из zml1)

`[^N]:` нумерованная (continuation = отступ 4 проб → `<br>`) · `[^]:` анонимная («См. также:»)
· `[^|преф]:` анонимная с кастомным префиксом. Нумерованные идут первыми, анонимные — после.

**Без новых атрибутов** (терсность):
- `kind` (ref/extended/term) → **ДЕРИВ** рендером (extended по длине; term по контенту);
  fn-wide / 1-кол. — CSS (→ Q16).
- `sourceType` («Музыка::», «Цитата::») → литерально уже в теле сноски (автор так пишет).
- `orphan` (нет `[^N]`-маркера в тексте) → **ДЕРИВ** рендером. Политика показа (Q11, decided):
  orphan рендерится как **анонимная карточка** (`<li class="anon">` без кнопки возврата `↩`, по
  модели `[^]:`) — не выдумывает ложной привязки. Импровизации тем (привязка к соседней сноске,
  отдельная зона «несвязанные») НЕ канонизируются.

## 5. КАПС, глифы, экранирование

- **КАПС литерально** как в источнике: без downcase, без bold, без `text-transform`.
  Small-caps + восстановление имён — на рендере (CSS + встроенный список); `^СЛОВО` дополняет.
- **Глифы/эмотиконы дословно:** `<\^/>`, `;;;;`, `;`, `^`, `::`, `;::)))`, `:)`, `; : )`,
  ивр. `;;; ;;;;` — контент данных, пунктуация НЕ нормализуется. Тема лишь красит/курсивит.
- **Escape `<\^/>`:** литеральный авторский знак; в HTML `&lt;\^/&gt;`. Документируется явно
  (в zml1 SPEC §5.8 отсутствовал — пробел закрыт). Внутри escape `^` спец-значения не имеет.

## 6. Карта миграции zml1 → ZML 2

| zml1 | ZML 2 | Трансформация |
|---|---|---|
| frontmatter, art-id, `## {slug}`, параграф | без изменений | identity |
| `[poem]` / `[poem title=]` | без изменений | identity |
| `[sub]`, `[mus]`+треки, `[^N]`/`[^]:`/`[^\|p]:` | без изменений | identity |
| `[^N]`, `[[art]]`, `{chapter\|N}`, `[url\|анкор]`, `_italic_`, CAPS, `^СЛОВО` | без изменений | identity |
| `[epi]` | `[epi kind=…]` | добавить `kind` (деф. `prose`; стиховые демо → `kind=verse`). Без kind = `prose`. |
| `[epi cite=]` | `[epi cite=]` | без изменений (роль source) |
| `[quote]` (спящий) | `[quote kind=scripture]` **активен** | включить; отделить от эпиграфа; `cite=` |
| `[epil]` (спящий) | **сворачивается в `[epi]`** (хвостовая позиция) | Q3 decided: отдельного тега нет; редкие вхождения → `[epi]`, метку «Эпилог» ставит рендер по позиции |
| `[num]` | `[num]` (семантика расширена) | тег тот же; теперь покрывает «нумер. разделы» и «тезисы», не только абзацы |
| — (не было) | `[sig]`, `[cry]` | новые блоки от дизайна |
| — (не было) | inline `term/leitmotif` | новый опц. inline-крючок (Q13); метит адаптирующая LLM по смыслу |
| — (не было) | `[img]`/`[dlg]`/список | зарезервированы спящими (`[dlg]` активируется на Фазе 4) |
| `<\^/>` (недокументир.) | `<\^/>` (документирован §5) | поведение то же, теперь в спеке |

**Что НЕ мигрирует (как в zml1):** footnote-section header, колофон-строки в теле,
авторские `Арт.#AP…`, голые URL — выбрасываются/генерируются/оборачиваются.

## 8. Authoring-guidance для адаптирующей LLM (кэшируемый контекст)

> Не правила синтаксиса, а инструкции модели при переносе ~350 статей в ZML 2. Живут в спеке
> (кэш prompt caching ≈ платим один раз). Закрывают суждения Q12/Q15.

- **Лейтмотивы/термины (`term/leitmotif`, Q13/Q12).** Помечай *редкие осмысленные* термины и
  лейтмотивы по своему суждению (напр. катнут/гадлут, ключевой повторяющийся образ). **НЕ меть
  высокочастотные сакральные формулы/доксологии** («Свят Благословен Он» и т.п.) — выделение
  десятков повторов зашумляет полосу (0/5 тем их метили). Текст таких формул переноси дословно,
  без пометки. Авто-детекцию не применять — только смысловое решение.
- **Сверхдлинные абзацы (Q15).** Периоды-«кирпичи» (до ~600 слов) переноси **«как есть»**: НЕ
  дроби на под-сегменты, НЕ реструктурируй, НЕ вставляй искусственных разрывов. Читаемость —
  забота темы (мера строки в `ch`). Под-сегментация вводится ТОЛЬКО при авторском членении в
  исходнике (лесенка/нумер. под-пункты), не агентским угадыванием. *(Кандидат на будущий
  эксперимент — смысловые строки/colometry; пока вне формата.)*
- **Голые URL (Q14).** В теле не оставлять: оборачивать в `[url|анкор]` / `[[art]]` /
  `{chapter|N}` / трек `[mus]`.

## 7. Сводка черновика

- **Блок-типов активных:** 10 (параграф, `##`-секция, `[poem]`, `[epi]`, `[quote]`, `[num]`,
  `[sub]`, `[mus]`, `[sig]`, `[cry]`) + 3 резерв (`[img]`,`[dlg]`,список). `[epil]` снят
  (= `[epi]` в хвосте, Q3).
- **Inline активных:** 8 (`[^N]`, `[[art]]`, `{chapter\|N}`, `[url\|анкор]`, `_italic_`,
  CAPS-pass, `^СЛОВО`, опц. `term/leitmotif`) + escape `<\^/>`. Резерва нет.
- **Унаследовано как есть:** вся структура, параграф, `[poem]`, `[sub]`, `[mus]`, все сноски,
  все inline, CAPS/глифы.
- **Обобщено:** `[epi kind=]` (+ функц. определение, эпилог деривируется), `[num]` (перечень),
  `[mus]` (тело+аппарат), section `role=` опц.
- **Ново:** `[quote]` (активир.), `[sig]`, `[cry]`, опц. inline `term/leitmotif`.
- **Authoring-guidance (§8):** доксологии не метим, длинные абзацы «как есть», голые URL оборачиваем.
- **Реестр решений:** 16/16 закрыто (`decisions_open_002.md`) — open-пунктов нет.
