# Аудит наследования формата ZML 1 → ZML 2 (корпус-управляемый)

**Дата:** 2026-05-29
**Вход:** только сторона zml1 (НЕ дизайн-темы).
**Источники:** `_zml_spec/SPEC.md`, `src/transform_prompt.md`, `src/3_transform.py`,
корпус `raw/*.html` (350 статей = `manifest.json`), легаси-структура `json/*.json`
(7 реальных статей), ручные образцы `zml/*.zml` (3 статьи: 237, 416A, 654).

---

## 0. Как устроена связка (что и где «zml-разметка»)

```
proza.ru raw HTML  ──3_transform.py──►  <art>.zml   ──4_render.py──►  site/*.html
   (raw/*.html)        (headless LLM)    (source of truth)
```

- **`raw/*.html`** — 350 статей-исходников proza.ru. Авторская семантика тут выражена
  «сырыми» соглашениями: `*`/`[1]` для сносок, `<a href="proza.ru/…">` для ссылок,
  строка-шапка «Музыка под настроение» + YouTube-ссылки, CAPS-строки для секций,
  «Арт.#…/Записано…» для колофона и т.п. **Именно raw даёт честную частоту корпуса.**
- **`json/*.json`** — ЛЕГАСИ-структура CMS («JSON-блочная структура», которую ZML
  и заменяет — SPEC §intro). Сохранилось только 7 файлов. Это не корпус, а **схема
  блоков**: `sections[].blocks[]` с `type ∈ {paragraph, poem, music, epigraph}`,
  отдельные `footnotes[]`, `xrefs[]`. Подтверждает набор блок-типов, но мал для частот.
- **`<art>.zml`** — целевой формат zml1 (то, что наследуем). В наличии 3 ручных
  образца. По ним видно, как операторские конструкции выглядят в чистом zml1
  (`[epi]`, `[poem]`, `[^N]`, `[[art]]`, `^СЛОВО`).

**Метод частот.** Я просканировал `<div class="text">` всех 350 raw-статей и сопоставил
авторские соглашения с zml1-конструкциями (таблицы соответствия — `transform_prompt.md`
§3/§6, `3_transform.py`). Плюс взял поля `manifest.json` (`img`, `text_date`,
`section`, `art`). Цифры по `[poem]`/`[num]`/`section` — эвристики (помечены «оценка»).

## 1. Карта формата zml1 (все блок-типы и inline-конструкции)

### Структура документа
| Конструкция | Семантика |
|---|---|
| **frontmatter** `---…---` (YAML) | `title`(обяз.), `summary`, `art`(обяз., id `XYZ[n]`), `date`, `image`, `editor`, `edited`. Контент-метаданные статьи; рендерит byline + colophon. |
| **art-id `XYZ[n]`** | Универсальный id, кодирует дату; суффикс `A..Z,a..z` для нескольких статей в день. Имя файла, цель `[[art]]`. |
| **порядок секций** | Жёсткий: frontmatter → intro-блоки → `## секции` → блок сносок в самом конце. `section_order` (см. `2b_section_order.py`) фиксирует порядок. |

### Блок-типы (`§4`)
| Тег | Семантика |
|---|---|
| **параграф** (default, без тега) | Базовый блок; авто-подвиды `attribution` (лид), `colophon` (генерится из FM). |
| **`## Заголовок {slug}`** | Секция h2; CAPS-текст рендер сам делает small-caps; slug опционален. |
| **`[poem]…[/poem]`** | Стих: построчно, лесенка-отступы сохраняются, авто-капитализация, `title=` опц. |
| **`[epi]…[/epi]`** | Эпиграф; `cite=` если автор в той же строке. Метка «Эпиграф». |
| **`[epil]…[/epil]`** | Эпилог (в SPEC «спящий»). |
| **`[quote]…[/quote]`** | Цитата/blockquote (в SPEC «спящий»); `cite=`. |
| **`[sub]…[/sub]`** | Подзаголовок-эхо H1 (часто с inline-сноской) → `<h2 class=subtitle>`. |
| **`[num]…[/num]`** | Нумерованная последовательность параграфов; рендер сам ставит «1. 2. 3.». |
| **`[mus]…[/mus]`** | Музыкальная группа; внутри трек-строки `[url|title|author]`; `[mus="label"]`. YouTube→плеер, иначе плоская строка/без-плеер. |

### Inline-конструкции (`§5`)
| Конструкция | Семантика |
|---|---|
| **`[^N]`** | Маркер сноски в тексте → `<sup>`+popup. |
| **`[[art]]`** | Внутренняя ссылка на статью yaniktoim; заголовок подставляет рендер из manifest. |
| **`{chapter\|N}`** | Ссылка на корпус Зоар (`zohar-sulam`); заголовок из `zohar_index.json`. |
| **`[url\|анкор]` / `[url]`** | Внешняя гиперссылка (голых URL быть не должно). |
| **`_фраза_`** | Italic-эмфаза (из авторских `[фраза]`, авто-конверт на python-этапе). |
| **CAPS-pass** | Целые CAPS строки/абзацы → small-caps `<span class=sb>`; имена собственные восстанавливаются. |
| **`^СЛОВО`** | Внутри CAPS-куска принудительно делает слово Заглавным (для Кли/Нагваль и пр.). |

### Сноски (тело, `§6`)
| Форма | Семантика |
|---|---|
| **`[^N]:`** | Нумерованная сноска; continuation — отступ 4 пробела → `<br>`. |
| **`[^]:`** | Анонимная, рендер ставит префикс «См. также:». |
| **`[^\|префикс]:`** | Анонимная с кастомным префиксом. |

### Не встречается в raw / только в SPEC или post-edit
| Конструкция | факт | примечание |
|---|---|---|

| **`^СЛОВО` маркер** | **0** в raw; **есть** в `237.zml` (`^ЛЮБИТЬ`, `^НАСТОЯЩЕМУ`, `Воина^Исраэль`) | Это **операторский** инструмент, добавляется на этапе ручной правки, не из автора. |
| **`[epil]`/`[quote]` как явные теги** | в SPEC «спящие» | синтаксис закреплён; активируются при первом срабатывании. |

> **Замечание по музыке:** из 231 статьи с YouTube только 127–153 имеют шапку
> «Музыка под настроение». Остаётся ~104 статьи, где видео/музыка живёт **в сносках

> То есть музыкальная семантика шире одного блока `[mus]`.

## 3. Вердикт наследования

### must-inherit (обязаны быть в ZML 2)
| Конструкция | Обоснование |
|---|---|
| **frontmatter** (`title/art/date/summary/image`) | id и метаданные — фундамент пайплайна; `date` 207/350, `image` 195/350, `art` у всех. |
| **art-id `XYZ[n]`** | Универсальный идентификатор; цель ссылок и имя файла. Несёт дату. |
| **порядок секций / `## {slug}`** | 184/350; жёсткий порядок (intro→секции→сноски) — структурный инвариант. |
| **параграф (default)** | Самый частый блок по определению. |
| **`[poem]`** | ≥112/350; корпус поэтический, лесенка/капитализация — несомая семантика. |
| **`[^N]` + `[^N]:` (пара ref↔fn)** | 197/350, 1347 вхождений. Ядро. |
| **`[^]:` / `[^\|преф]:` аноним. сноски** | 77/350; отдельная семантика «См. также:» без якоря. |
| **`[[art]]` внутренние ссылки** | 111/350, 266 вхождений — плотная сеть перекрёстных ссылок корпуса. |
| **`{chapter\|N}` Зоар-ссылки** | Частота в raw = 0, **но**: спец §5.5 полностью спроектирована, индекс собран, это связь с сопутствующим корпусом Зоар. Добавляются при post-edit. **Наследуется по замыслу.** |
| **`[url\|анкор]`** | 25/350, но без неё нельзя выразить внешние ссылки (нет голых URL). |
| **`[mus]` + `[url\|title\|author]`** | музыкальная семантика в 231/350 (по YouTube). Несомый, недизайнерский блок. |
| **CAPS-pass + `^СЛОВО`** | CAPS 193/350; `^СЛОВО` — операторский маркер для имён вне встроенного списка, используется в ручных zml. |
| **`[epi]`** | 64/350 + подтверждён json-схемой (block type `epigraph`). |
| **`[sub]`** | ~100/350 статей дублируют H1 первой строкой; убирает дублирование + держит inline-сноску. |
| **`_фраза_` italic** | 33/350; единственный носитель эмфазы (других нет). |

### под вопросом (решим при проектировании ZML 2)
| Конструкция | Почему |
|---|---|
| **`[num]`** | Реальная проза-нумерация почти не встречается (0 в 3 zml; raw-счёт завышен музыкой). Можно оставить, но не приоритет; рассмотреть, не выразить ли нумерацию иначе. |
| **`[quote]`** | 28/350 по форумному маркеру; в SPEC «спящий». Семантика реальна (диалоги/цитаты), но распознавание шаткое — нужно решить правила. |
| **`[epil]`** | 5/350 кандидатов. «Спящий». Дёшево унаследовать как зеркало `[epi]`. |
| **`title=` у `[poem]`, `cite=` у `[epi]/[quote]`** | Атрибуты редки; решить, нужны ли в ZML 2 или выражаются иначе. |

### deprecated / сворачивается (можно убрать или выразить иначе)
| Конструкция | Чем заменить |
|---|---|
| **footnote-section header** («Пост скриптум/Примечания/Сноски») | Не контент — служебный заголовок. В zml1 уже выкидывается; в ZML 2 блок сносок самоопределяется тегами `[^…]:`. |
| **колофон-строки** («Арт.#…», «Записано…») в теле | Не блок: целиком генерируется из `frontmatter.art/date`. В теле не хранить. |
| **авторский `Арт.#AP…`** | Заменён каноническим `art`-id. |
| **голые URL** | Запрещены; всегда оборачивать (`[url]`/`[[art]]`/`{}`/трек). |

## 4. Особое внимание — НЕДИЗАЙНЕРСКАЯ семантика

Конструкции, которых **не было в дизайн-макетах (2 статьи)**, но которые корпус
доказал как нагруженные смыслом — кандидаты, иначе потерялись бы:

1. **Внутренние ссылки `[[art]]`** — 111/350, 266 вхождений. Перекрёстная сеть корпуса;
   рендер подставляет заголовок из manifest. **Критично.**
2. **Зоар-ссылки `{chapter|N}`** — 0 в raw, но машинерия (`zohar_index.json`, 5 глав)
   и спека готовы; связь с внешним корпусом Зоар, добавляется при post-edit. **Нельзя терять.**
3. **Музыка `[mus]` + трек-формат** — 231/350 по YouTube. Плеер/lazy-iframe/группировка;
   плюс «теневая» музыка в сносках (`Музыка: X — Y`) у ~104 статей.
4. **Изображения** — `frontmatter.image`; задано у 195/350 (`manifest.img`).
5. **Порядок секций** — intro→`##`→сноски-в-конце; `section_order` (`2b_section_order.py`).
   Жёсткий инвариант рендера.
6. **Спец-инлайны:** `^СЛОВО` (заглавная внутри CAPS — 0 в raw, есть в ручных zml),
   CAPS-pass с восстановлением имён собственных, `_фраза_` italic.
7. **Анонимные сноски `[^]:` / `[^|преф]:`** — 77/350; «См. также:»-семантика без якоря.
8. **art-id, кодирующий дату** — сортировка/вставка статей без сдвигов.

> Найден также недокументированный escape-токен `<\^/>` в `237.zml` (стр. 10) —
> по-видимому, способ внести литеральный `^` рядом с `^СЛОВО`-маркером. **Не описан в
> SPEC §5.8** — отметить при проектировании экранирования ZML 2.

## 5. Заметки для слияния с дизайн-семантикой (Фаза 2b) — НЕ объединять здесь

Точки пересечения zml1 ↔ найденного дизайнерами (только пометки):

- **Эпиграф `[epi]`** — был и в дизайн-макетах, и в корпусе (64/350, `cite=`, метка
  «Эпиграф», несколько подряд). → объединить модели «метка + источник».
- **Сноски `[^N]`/popup** — дизайн показывал hover-popup; корпус даёт массу (1347)
  + анонимные + многострочные стихотворные сноски. → согласовать модель сноски
  (нумерованная / анонимная / continuation / inline-ссылки внутри тела).
- **Поэма `[poem]`** — дизайн рендерил стих; корпус добавляет: лесенка-отступы,
  построфные пустые строки, CAPS-строфы→small-caps, `title=`. → объединить с учётом
  авторской типографики.
- **Цитата `[quote]` / Эпилог `[epil]`** — если дизайн их предусматривал, сверить с
  «спящими» тегами SPEC §4.5/§4.6 перед активацией.
- **Заголовки/секции** — дизайнерская типографика h2 ↔ CAPS-семантика + slug-якоря.
- **Музыка** — дизайн-плеер ↔ корпус-реальность (группы, без-плеер, теневая музыка
  в сносках). → расширить дизайн-модель под недизайнерские случаи.

Само объединение — задача Фазы 2b; здесь только зафиксированы стыки.
