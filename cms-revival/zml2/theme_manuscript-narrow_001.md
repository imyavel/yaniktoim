# Theme Spec — `manuscript-narrow` (v001)

> Воспроизводимая спецификация темы «Иллюминированный манускрипт (узкий)».
> Извлечено из `variant_manuscript/index.html`. Все значения — фактические из CSS макета.
> Назначение: ZML 2, слой оформления. Один семантический источник → эта тема как один из вариантов рендера.

---

## 1. Идентичность темы

- **Имя:** `manuscript-narrow`
- **Эстетика:** иллюминированный пергаментный свиток / средневековая рукопись. Рубрикация красным (rubric), золотые флероны, буквицы (drop-caps), тёплый светлый пергаментный фон, гуманистическая антиква.
- **Общее впечатление:** сакральный/литургический документ; торжественный, тёплый, «ручной». Светлая тема (НЕ тёмная).
- **Контейнер:** `main.scroll`
  - `max-width: 780px`, `margin: 0 auto` (одноколоночный центрированный «лист»).
  - `padding: clamp(26px,6vw,72px) clamp(20px,6vw,74px) clamp(40px,7vw,80px)` (низ больше верха).
  - `border: 1px solid #e3d3ab` (`--parch-edge`), `border-radius: 3px`.
  - Многослойная тень: внутренний светлый кант + золотистый хайлайт-кант + мягкая drop-shadow `0 30px 70px -30px rgba(58,46,33,.42)`.
  - **Двойная золотая внутренняя рамка:** `.scroll::before` (`inset: clamp(10px,2.4vw,20px)`, `1px solid rgba(169,129,47,.45)`) и `.scroll::after` (`inset: clamp(14px,3vw,26px)`, `1px solid rgba(169,129,47,.20)`).
  - **Угловые флероны:** `.corner.tl/tr/bl/br` — символы `❦`/`❧` (10086/10087), Cormorant Garamond, `--gold`, `font-size: clamp(20px,3.4vw,30px)`, `opacity: .85`.
- **Внешний отступ страницы (body):** `padding: clamp(14px,4vw,56px) clamp(10px,4vw,40px)`.
- **Сетка:** строго одна колонка. Внутренние «дорожки» через `max-width` в `ch` (см. §4–5), всё центрируется `margin-inline: auto`.

### Ограничения шкалы (ревью #1)
- **Потолок заголовка:** макс `3.15rem` (≈50–60px) — разумно, потолок не превышать.
- **Пол читаемого текста:** «текстовое тело» (сноски, проза) не мельче `0.9rem` (≈14.4px). Соблюдено: пункты сносок = `0.9rem`.
- **Метки/трекинг-капс** (`.eplabel`, `.genre`, `.ord`) = `0.72–0.8rem` — это НЕ читаемое тело, а трекинговые ярлыки uppercase; допустимы, но **пол для них фиксируем `0.72rem`** (ниже не опускать).
- **Отношение макс/мин (по содержательному тексту):** `3.15rem / 0.72rem ≈ 4.4×` — в пределах нормы.
- **Вердикт:** шкала исходника сбалансирована, гигантских заголовков и невидимых сносок нет. **Коррекция не требуется.** Единственная рекомендация — закрепить пол `0.72rem` для трекинг-меток и пол `0.9rem` для любого читаемого тела как инвариант темы.

## 5. Модель стиха

- **Одноколоночная.** Все строки идут сверху вниз одной колонкой; никаких параллельных колонок нет.
- **Стрелки-коннекторы направления чтения НЕ нужны** (они требуются только в многоколоночных моделях для указания порядка чтения).
- **Строка:** `.vline { display:block; line-height:1.62; font-size:1.06rem }` — каждая строка стиха = отдельный блок.
- **Строфа:** `.stanza { margin-bottom:1.6em }`; вариант сплошного потока `.stanza.flow { margin-bottom:1.4em }` (для длинных непрерывных пассажей — Стих 2 финал, весь Стих 3).
- **Ширина набора стиха:** `.verseblock { max-width:38ch; margin:1.4em auto 0 }`; широкий вариант `.verseblock.wide { max-width:46ch }`. На `max-width:560px` → `100%`.
- **Разбивка на строфы:** катрены/группы разделены вертикальным `margin` между `.stanza`. Семантическая граница строфы в исходных данных — двойная пустая строка; в рендере она превращается в отдельный `.stanza`.
- **Буквица** открывает первую строку строфы/стиха (`В`, `К`, `У`), обтекается текстом (`float:left`).

## 6. Сноски

- **Модель:** надстрочные числовые якоря в тексте + концевой нумерованный список («Полезные ссылки»).
  - Якорь в тексте: `<sup class="fn"><a id="ref-N" href="#fn-N">N</a></sup>`.
  - Пункт списка: `<li id="fn-N"><span class="fn-num">N</span>…<a class="fn-back" href="#ref-N">↩</a></li>`.
- **Навигация туда-обратно:** вперёд по `href="#fn-N"` (к пункту), назад по `.fn-back href="#ref-N"` (стрелка `↩` 8617). `.fn-back` — `--gold`, `0.85em`, hover → `--rubric`.
- **Номер пункта:** `.fn-num` — абсолютно спозиционирован слева (`width:2em; text-align:right`), Cormorant 700, `--gold-deep`.
- **Разделители внутри пункта:** `.sep` (`::`) — `--ink-mute`, `padding:0 .15em` (сохраняются дословно, см. §7).
- **Внешние URL:** `.notes a[href^="http"]` — `--indigo`, `border-bottom:1px dotted rgba(52,80,112,.4)`, `word-break:break-word`; hover → `--rubric`.
- **Под-пункты** (сноска 29): `.fn-sub { display:block }`, маркеры `::1::…::4::` в `<b>` цветом `--gold-deep`.
- **Пустая сноска** (22): показывается как тире `—` (`--ink-mute`, italic).

### BASELINE-требование (ревью #3): подсветка активной сноски через `:target`
**В исходном макете правила `:target` НЕТ — это пробел, обязательный к закрытию во всех темах.** Добавить:

```css
ol.fnlist li:target{
  background: rgba(169,129,47,0.12);              /* мягкий золотой фон */
  box-shadow: inset 3px 0 0 var(--gold-deep);     /* золотая линия слева */
  border-radius: 2px;
}
ol.fnlist li:target .fn-num{ color: var(--rubric); }  /* номер → рубрика */
/* зеркально для возврата к якорю в тексте */
sup.fn a:target,
*:target > sup.fn a{ outline: 2px solid rgba(169,129,47,.4); border-radius:2px; }
```
- **Внешний вид активной цели:** тёплый золотой фон `rgba(169,129,47,.12)`, вертикальная золотая линия слева (`inset 3px 0 0 --gold-deep`), номер сноски перекрашивается в рубрику `--rubric`. Согласовано с палитрой темы (золото + красный).

## 7. КАПС и глифы

- **КАПС оставляем ЛИТЕРАЛЬНО** как в источнике: без `text-transform`, без принудительного `lowercase`, **без болда**. Капс-пассажи (`.ascend`, эпиграфы-проза, рефрены) набраны заглавными прямо в данных; тема лишь добавляет `letter-spacing:.04em` и тёплый цвет `#5a4226` для `.ascend .vline`. Никакой нормализации регистра.
- **Глифы/эмотиконы сохраняем дословно** (в данных — как литеральный текст, экранируется только HTML):
  - `<\^/>` — авторский «герб» в заголовке → `h1.title .glyph` (Cormorant italic, `--gold-deep`).
  - `;::)))`, `;;;;`, `;`, `^`, `::1::`, `::2::`, `::` — встроенные глифы → `.glyph` / `.glyph-inline` (`--gold-deep`/`--gold`), inline, без изменения символов.
  - `^` в «Воина^Исраэль», «по^настоящему» — оставить как есть (литеральный символ, не верхний индекс).
- **Подача:** глифы окрашиваются золотом (`--gold` / `--gold-deep`), часто italic; служат литургическими врезками/акцентами, но **текстовое содержимое не меняется** — только цвет/курсив/трекинг.

## 8. Семантика vs оформление

### A. Чисто CSS (уходит в тему — данные не меняются)
- Все цвета, шрифты, размеры, радиусы, тени, градиенты, бордюры.
- Пергаментный фон, рамка-свиток, двойная золотая рамка, угловые флероны.
- Буквица (drop-cap) первой строки стиха — чисто визуально (можно вывести из «первая строфа стиха»).
- `letter-spacing`, uppercase-трекинг меток, `text-wrap:balance`, `hyphens`.
- Подсветка `:target` (§6) — оформление поверх якорной модели.
- Цвет/курсив глифов, тёплый тон `.ascend`.
- Рукописный `.amen` (можно вывести из паттерна «Амэн…»).
- Чередование символов флеронов между разделителями.

### B. Требует семантического различия в ДАННЫХ (ZML 2 — общий слой)
- **Подтип эпиграфа:** `verse` vs `prose` — разный набор/выключка/курсив. Данные должны нести признак «эпиграф-стих» / «эпиграф-проза».
- **Тип блока-цитаты/сентенции:** «катнут»-афоризм (`.katnut`) vs обычный эпиграф vs «строка-форма» (`.formline`) vs «инвокация» — это разные семантические роли, не выводимые из вёрстки.
- **Нумерация / порядок главы:** `.chapter .ord` («Стих первый» / «Предваряющая») + имя главы — данные должны различать «порядковую метку» и «заголовок», а также тип секции (молитва vs стих).
- **Модель сноски (роль пункта):** «См. также» (внутренняя отсылка) vs «Музыка» vs «Цитата» vs внешний URL vs пустая (22) vs составная с под-пунктами (29) — семантика типа источника; разделители `::` и под-маркеры `::1::` несут структуру, а не оформление.
- **Якорная пара ref↔fn:** связь маркер↔пункт↔возврат — семантическая (id/href), тема лишь её стилизует.
- **Капс как авторский регистр:** КАПС несёт авторский смысл (крещендо/литания), поэтому он в ДАННЫХ литерально, а не `text-transform`. Признак «восходящий/усиленный пассаж» (`ascend`) — пограничный: можно вывести из капса, но надёжнее нести флагом в данных.
- **Глифы-врезки** (`;;;;`, `;`, `^`, `<\^/>`): литеральный контент данных; их наличие/позиция семантичны, цвет — оформление.
- **Строфические границы** (двойная пустая строка → `.stanza`): структура данных; вертикальный ритм — оформление.
- **Метка эпиграфа** «Цитата · Эпиграф N ()» — текст в данных (включая `()`); капс/трекинг — тема.
