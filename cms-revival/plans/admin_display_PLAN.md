## 0. Цель одной фразой
По умолчанию и для всех показываем **старый HTML**; наверху каждой старой страницы — кнопка
на **новую (ZML) версию**. Появляется мини-«админка» (вход с главной, логин по нику через
существующий Cloudflare-Worker), где каждый пользователь настраивает: (1) дефолт показа old/new,
(2) **таблицу правил** «раздел/тип → дизайн + ширина» для ZML-вью. Настройки **Admin** = глобальный
дефолт для всех без логина; **Nipna/Anibe** — личные, применяются после их логина.

## 1. Ратифицированные решения (не трогать без «go»)
1. **Дефолт = старый HTML.** Прежняя модель доступа Ф9 (клик по названию → ZML) **отменяется**;
   вместо неё old-by-default + переключатель.
2. **Приоритет темы/ширины = front-matter всегда главнее.** НО per-article `theme:`/`width:`
   **обнуляются** во всех статьях; умолчания переезжают в «общие метаданные» (центральный конфиг:
   глобальный дефолт + таблица правил). Поле в front-matter остаётся доступным как осознанный
   per-article override (редактор может задать), но по умолчанию пустое.
3. **Стиль (дизайн/ширина) действует ТОЛЬКО на ZML-вью.** Старый HTML отрисован жёстко и не
   переключается; админка управляет лишь тем, в какой теме/ширине открывается ZML-вью.
4. **Тип работы — свойство front-matter `type:`**, выводится автоматически (см. §3). 5 значений:
   `verse` (обычный стих) · `poem` (поэма) · `prose` (проза) · `dialog` (диалоги) ·
   `prose_num` (проза с нумерованными абзацами).
5. **Пользователи через Cloudflare-Worker:** базовый **Admin** + **Nipna** + **Anibe**. У каждого —
   своя независимая админка/таблица. **Admin**: его настройки = дефолт для анонимов; в колофоне он
   отображается как сейчас — «Редакция: Иван Иванович» (= `fm.editor` по умолчанию, осознанная
   ИИ-метка, см. [[project_yaniktoim_ivan_ivanovich_ai_mark]]). Nipna/Anibe в колофоне — свой ник
   (при их правках `fm.editor` перезаписывается ником, как уже работает в `/api/save`).

## 2. Резолвинг темы/ширины для ZML-вью (клиентский, в `<id>.view.html`)
На загрузке вью вычисляет эффективные (design, width) так:
1. **Если** в front-matter статьи явно задан `theme:`/`width:` (per-article override) → берём его.
   (После обнуления §1.2 это редкий случай.)
2. **Иначе** применяем таблицу правил эффективного пользователя сверху вниз: **первое** правило,
   чьё условие (раздел статьи ИЛИ её `type:`) совпало, даёт design+width. Один список, приоритет = порядок строк.
3. **Иначе** глобальный дефолт сайта (design+width).

**Эффективный пользователь:** залогинен (Nipna/Anibe) → его настройки из Worker KV; аноним →
опубликованные настройки Admin (статический конфиг в репо). Каждый пользователь имеет ПОЛНУЮ
собственную таблицу (не оверлей над Admin).

Вью должна знать **свой раздел и `type:`** — `build_views.mjs` инжектит их в вью (data-атрибуты /
JSON-островок) из `manifest.json` (раздел) и из ZML (`type`). FOUC: применять тему как можно раньше
(инлайн-скрипт в `<head>` перед первой отрисовкой `<article>`).

## 3. Деривация `type:` (в конвертере `convert/html_to_zml.py`; бэкфилл для 352)
Порядок проверок (первое сработавшее):
1. есть блоки `[dlg]` → `dialog`;
2. есть `[num]` (нумерованные абзацы) → `prose_num`;
3. стихотворная вещь И оглавление ≥ 2 разделов → `poem`;
4. стихотворная вещь (оглавление < 2) → `verse`;
5. иначе → `prose`.
**Уточнить при реализации** точный признак «оглавление/раздел» (вероятно число `[sub]`-подзаголовков;
сверить с `editor/render.js` парсингом TOC) и признак «стихотворная вещь» (доля `p.line` / verse-блоков).
Редактор может переопределить `type:` вручную. Записать `type:` в front-matter всех 352.

## 4. Модель данных
### 4.1 Front-matter статьи (`*.zml`)
- **Удалить** дефолтные `theme:`/`width:` из всех 352 (`convert/out/*.zml` и `../yaniktoim/docs/art/*.zml`),
  поле оставить «разрешённым, но пустым». Конвертер перестаёт авто-проставлять их (§1.2).
- **Добавить** `type:` (§3).
- Остальное (`title/art/date/image/audio/...`) — без изменений.

### 4.2 Центральный конфиг (= «общие метаданные» / настройки Admin → статика для анонимов)
Файл в репо, публикуется со статикой (предлагается `yaniktoim/docs/config/display.json`; сверить с
существующим `config/site.json` / `docs/editor/data/site.json` — возможно расширить его, не плодить):
```json
{
  "default_view": "old",                      // old | new — дефолт показа для анонимов
  "global": { "design": "A_editorial", "width": "wide" },
  "rules": [                                   // приоритет = порядок массива
    { "match": { "kind": "section", "value": "best" },  "design": "swiss",      "width": "wide"   },
    { "match": { "kind": "type",    "value": "poem" },  "design": "B_manuscript","width": "narrow" }
  ]
}
```
Редактирование этого объекта Admin'ом → коммит файла Worker'ом (как `/api/save`).

### 4.3 Настройки пользователя (Nipna/Anibe) — Worker KV, ключ по нику
Тот же объект, что 4.2 (`default_view` + `global` + `rules`), но личный. Не публикуется в статику;
отдаётся только авторизованному владельцу.

### 4.4 Списки для UI
- **Разделы (7):** `shoshana, dabudet, dreamon, best, confront, cyberson, other` (из `manifest.json`).
- **Типы (5):** `verse, poem, prose, dialog, prose_num`.
- **Дизайны (5):** `A_editorial, B_manuscript, ar_deco, cyberpunk, swiss` (из `cms-revival/themes/`).
- **Ширины (2):** `narrow` (~820) / `wide` (~1080).
Поле «раздел/тип» в строке таблицы — **один общий select** (опции = разделы + типы), не два поля.

## 5. UI
### 5.1 Главная (`docs/index.html`)
- Контрол «Войти» (логин по нику/паролю → Worker `/api/login`). После логина — кнопка «Админка».
- Для анонима ничего не меняется визуально, кроме появления входа.

### 5.2 Админка (страница `docs/admin.html` или модалка; решить при реализации)
- Тумблер **default_view** (old/new).
- **Таблица правил:** кнопка «+» добавляет строку [select раздел|тип] · [select дизайн] · [select ширина];
  строки = таблица; кнопки **↑/↓** двигают строку (меняют приоритет); кнопка удаления строки.
  Изначально таблица пустая (= только `global`).
- Поле глобального дефолта (`global.design/width`).
- Кнопка «Сохранить»: Admin → коммит `display.json` (Worker); Nipna/Anibe → запись в KV (Worker).
- Доступ к админке — роль из Worker (`admin` правит общий конфиг; `editor` правит свой KV).

### 5.3 Старая страница статьи (живой `docs/<section>/<art>.html` — путь сверить; по `/api/save` это
`docs/<section>/<art>.html`, в roadmap-входах упоминался `docs/art/*.html` — **проверить фактическое
расположение** перед правкой)
- Инжектить общий шим (один `<script>`/include на все старые страницы):
  - рисует верхнюю кнопку **«Новая версия (ZML)»** → ссылка на соответствующий `…/art/<id>.view.html`;
  - читает эффективный `default_view` (аноним → `display.json` Admin; залогинен → KV);
    если `new` → **редирект** на вью; если `old` → остаёмся.
  - показывает состояние логина (войти/выйти).

### 5.4 ZML-вью (`docs/art/<id>.view.html`)
- Кнопка **«Старая версия»** → ссылка на старую html.
- Существующий переключатель темы(5)/ширины(2) остаётся (ручной просмотр), но **начальное**
  состояние берётся из резолвинга §2.

## 8. Верификация (как проверять; картинки в контекст — ТОЛЬКО JPEG)
- **Тип:** выборочно 10–15 статей всех 5 типов → `type:` верный (особо: поэма vs стих по оглавлению≥2;
  диалоги; нумерованная проза). Спорные — глазами.
- **Резолвинг:** локально подставить тестовый `display.json` и проверить: (a) пустая таблица → всем
  `global`; (b) правило `section=best→swiss/wide`; (c) правило `type=poem→manuscript/narrow`;
  (d) приоритет порядка строк (поэма в best — по верхней строке); (e) per-article override в front-matter
  бьёт таблицу. Осмотр — `convert/viewshots.py <id>` + `--theme`/`--width`.
- **Старая→новая:** на старой странице кнопка ведёт на верный `<id>.view.html`; при `default_view=new`
  аноним редиректится на вью; при `old` — нет. Обратная кнопка во вью работает.
- **Пользователи:** логин Admin → правка `display.json` долетает коммитом, аноним видит изменения;
  логин Nipna → его таблица применяется только ему, аноним не затронут; колофон: Admin=«Иван Иванович»,
  Nipna=ник при правке.
- **Worker:** `/api/settings` GET/PUT под Bearer; `/api/settings/global` только admin; CORS с
  `imyavel.github.io`.
