# roadmap3.md — смена направления: прямая LLM-вёрстка по текстовому промпту в две стилевые схемы (без образцов, без ZML)

**Дата:** 2026-05-30
**Статус:** ДЕЙСТВУЮЩЕЕ направление. Замещает прежний план (`roadmap.md`, `roadmap2.md` в этом репо
и `design-experiment\roadmap1.md`).

---

## 0. Решение (заморозка)

**Проект в нынешней форме ЗАМОРАЖИВАЕТСЯ** — и та форма, что была в `yaniktoim` (редактируемый
CMS / рендер-пайплайн), и та, что в `design-experiment` (ZML 2 как семантический источник + 5 тем-
скинов + доказательство обратимости Фазы 3). Наработки сохраняются как есть (см. §5), но как
направление развития — стоп. `design-experiment\roadmap1.md` помечен «заморожено», в нём полная
запись прогресса на случай разморозки (ворота Фазы 3 были пройдены).

**Причина смены:** вместо семантического слоя (ZML 2) + выбора темы пользователем — **две
фиксированные стилевые схемы** (редакторская широкая / манускрипт узкая), в которые статьи
переводит LLM **напрямую, по одному текстовому указанию**, БЕЗ каких-либо образцов: ни готовых
HTML-макетов, ни выдержек из них, ни тема-спек, ни ZML. Стиль задаётся только словами промпта
(`batch_runner\convert_prompt_001.md`).

---

## 1. Новый подход — суть

1. **Две встроенные стилевые схемы**, авто-выбор по форме статьи:
   - **манускрипт** (узкий) — для стихов/поэм;
   - **редакторский** (широкий) — для прочих форм прозы;
   - смешанное — по доминирующей форме; при сомнении — редакторский широкий.
2. **Без образцов.** Стиль реализует LLM ТОЛЬКО по текстовому указанию
   (`batch_runner\convert_prompt_001.md`) — никаких готовых HTML, выдержек, тема-спек или ZML.
   Вход на статью = только её сырой текст.
3. **Все ~350 статей последовательно** переводятся в готовые самодостаточные HTML-страницы;
   **авто-публикация** по ходу.
4. **Редактирование страниц временно отменяется:** кнопка логина и редактирования исчезает с сайта.

---

## 2. Метод: чистый промпт, без образцов

Это сознательный отход и от ZML, и от модели 2-й статьи. Тогда («ТОЛЬКО ТЫ БУДЕШЬ ЖИТЬ ВЕЧНО»,
Фаза 1b) агенту давали **ориентир-образец** — тема-спеку `theme_<name>.md` (дистиллят дизайна) +
текст. Новое решение **отказывается и от образцов**: стиль задаётся исключительно словесным
описанием в `convert_prompt_001.md`; ни HTML-макетов, ни выдержек, ни спек, ни ZML на вход не подаётся.

Базовое указание (обогащённый вид — в `batch_runner\convert_prompt_001.md`):
> Два стиля — редакторский и манускрипт. Манускрипт — узкий для стихов/поэм, редакторский — широкий
> для прочих форм прозы. Избегать слишком мелких и слишком крупных шрифтов. Контрастные цветовые
> схемы на светлом фоне. Никакие названия не менять, своих заголовков и вставок не добавлять, не
> фантазировать. Вставки музыки и сноски оформлять согласно формату.

Перенос на продакшен:
- источник на статью — только **сырьё текста** (`raw/*.html` / тело proza.ru); никаких образцов;
- результат — самодостаточный HTML, сразу к выкладке;
- никакого ZML / таксономии / тем-реестра / выбора темы пользователем.

---

## 2.1 Формат музыки и сносок (канон — в `convert_prompt_001.md`)

«Согласно формату» из базового указания означает требования, прописанные в
`batch_runner\convert_prompt_001.md` (там — канонический текст; ниже — сводка):
- **Музыкальные подборки:** группа треков под заголовком («Музыка под настроение» / «Песнь
  Ступеней»); YouTube-трек = свёрнутый раскрывающийся плеер с **ленивой подгрузкой при раскрытии**
  (стрелка + «↗»); другая платформа = плоская ссылка; без ссылки = строка-заголовок; заголовок
  один раз над группой.
- **Сноски:** переходы вверх/вниз + **всплывающий popup при наведении** на маркер + подсветка
  активной сноски.
- **Верность тексту:** весь текст; названия/заголовки не менять, своего не добавлять; КАПС
  литерально; авторские глифы дословно; чистить только мусор импорта (`;`×2+).

## 3. Пайплайн исполнения — через существующий `batch_runner`

Используем уже готовый `yaniktoim\batch_runner\gui.pyw` (+ `run_batch.py`, `state.json`, `run.lock`):
последовательный цикл по статьям, Start/Stop, лог, докуда дошли — в `state.json`.

Требования к прогону:
- **Последовательно по всему корпусу** (порядок — по каталогу/manifest), с сохранением прогресса
  и докаткой после остановки.
- **Перепрыгивание через hit-limit / лимиты подписки Max-5:** при упоре в лимит — ждать/повторять/
  переходить к следующей итерации без падения цикла (как и задумано в раннере).
- **Авто-публикация** результата каждой статьи (сборка + push), как делает текущий батч.
- Модель — Opus 4.8 (по правилам репозитория), headless.

> Конкретные правки `gui.pyw`/`run_batch.py` под «прямую вёрстку по промпту» (подстановка
> `convert_prompt_001.md` + сырого текста статьи в запрос, запись готового HTML в `docs/`) —
> отдельная задача реализации; здесь зафиксировано целевое поведение.

## 4. Сайт — отключение редактирования

- Убрать кнопку **логина** и **редактирования** со страниц (вход в редактор недоступен).
- Страницы становятся статическими (только просмотр). Решение временное — на период перевёрстки;
  возврат редактирования — отдельным решением позже.

## 5. Что заморожено и что переиспользуется

**Заморожено (не развиваем):** ZML 2 формат и спека (`design-experiment\ZML2_SPEC_010.md`),
таксономия/реестр решений, 5-тем-как-скины + контракт классов (`proof1\render.mjs`), идея выбора
темы пользователем, редактируемый CMS. Всё это остаётся в репозитории как архив/задел.

**Переиспользуется:** `batch_runner` (gui.pyw/run_batch.py) как движок последовательного прогона и
публикации; сырьё статей (`raw/`, manifest); инфраструктура сборки сайта (`docs/`). 5 эталонных
HTML-дизайнов и тема-спеки из `design-experiment` **как вход НЕ используются** (стиль — только из
промпта); остаются в архиве как референс/история.

## 6. Открытые пункты / следующие шаги

1. **Доработать `convert_prompt_001.md`** при необходимости (характер двух стилей, граничные случаи
   выбора схемы, типографские пределы). Базовая версия — готова.
2. **Подключить промпт к `batch_runner`** (`run_batch.py`): на статью — `convert_prompt_001.md` +
   сырой текст → готовый самодостаточный HTML в `docs/`.
3. **Снять логин/редактирование** с сайта (только просмотр).
4. **Прогон по корпусу** с авто-публикацией и обработкой hit-лимитов; выборочный QA результата.

> Выбор «1 из 5 дизайнов» снят: направление зафиксировано на **двух схемах, задаваемых только
> промптом** (без образцов).
