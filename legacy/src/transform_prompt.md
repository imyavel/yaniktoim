# Промпт для headless `claude -p` (Opus 4.8) — HTML → ZML

Ты получаешь подготовленный plain-text одной статьи Элиягу Бар Малея с proza.ru. Ссылки уже размечены маркерами `⟦INT⟧` / `⟦ZOH⟧` / `⟦EXT⟧` (см. ниже). Твой вывод — финальный текст в формате **ZML** (yaniktoim Markup Language) с YAML-frontmatter, готовый к сохранению как `<NNN>.zml`.

Полная спецификация формата — `_zml_spec/SPEC.md`. Этот промт описывает только **переход HTML → ZML** и краевые случаи распознавания авторских конструкций.

---

## 1. Главное правило — текст неприкосновенен

Твой вывод — **тот же самый текст** исходника, только размеченный ZML-тегами и поделённый на frontmatter + тело. Текст после снятия разметки должен совпадать с подаваемым на вход **посимвольно** (с учётом разрешённых ниже изменений).

### Запрещено

- Менять кавычки. `"` → `"`. `«»` → `«»`. **Не «облагораживать» типографику.**
- Менять тире (`-`, `—`, `–` — как в исходнике).
- Менять регистр букв. CAPS-фразы оставляй CAPS — ZML-рендер сам делает small-caps.
- Исправлять опечатки, грамматику, пунктуацию.
- Пересказывать, сокращать, добавлять, перефразировать.
- Удалять пустые строки, пробелы, неразрывные пробелы внутри блоков.
- Менять порядок строк, слов, символов.
- Сам расставлять `<em>`, `<strong>`, `<span>`, или ZML-эквиваленты для эмфазы — таких тегов в ZML нет, рендер обходится CAPS и SB-pass.
- Применять inline-разметку (`[^N]`, `[[nnn]]`, `{chapter|N}`, `[url|анкор]`) к тексту, в котором их в исходнике не было. ZML inline вставляется только там, где это диктуют входные маркеры (см. §3) или таблица распознавания сносок (см. §6).

### Разрешено (единственные допустимые изменения текста)

1. **Свернуть inline-маркеры ссылок** `⟦INT⟧` / `⟦ZOH⟧` / `⟦EXT⟧` в ZML-эквиваленты (см. §3). Анкоры (видимый текст) сохраняются.
2. **Перевести авторские сносочные токены** (`*`, `**`, `***`, `*4`, `[1]`, `[¤ 5]`, `[¶.3]`, `[‡ 2]`, `[ezer-kenegdo 6]`, `[b-a 7]` и им подобные — см. §6) в `[^N]` (inline) и `[^N]:` (тело сноски). Нумерация — последовательная в порядке появления **в основном тексте**, начиная с 1.
3. **Удалить colophon-строки** из тела (Арт.-номера автора и текстовые даты, см. §5). Их содержимое — частично переезжает во `frontmatter.date`, частично теряется (авторский Арт.# не сохраняется, у нас свой `id`).
4. **Удалить служебные заголовки сносочного блока** в исходнике («Пост скриптум», «Примечания», «Сноски» — отдельной строкой в конце статьи перед списком сносок). В ZML этих заголовков нет — список сносок размечается тегами `[^N]:` и стоит в самом конце документа.

## 2. Структура выхода

```
---
title: <h1 исходника>
summary: <1–2 предложения ≤ 160 символов>
art: <арт-id, подставит python>
date: <если в теле была авторская дата>
---

<intro-блоки до первой «##»>

## <ЗАГОЛОВОК СЕКЦИИ> {slug-секции}

<блоки внутри секции>

## <следующая секция>
...

[^1]: <тело сноски 1>
[^2]: <тело сноски 2>
...
```

**Что заполняешь:**

| Поле | Откуда | Замечания |
|------|--------|-----------|
| `title:` | первая `H1`-строка исходника | без кавычек, без CAPS-преобразования. Если в исходнике CAPS — оставь как есть, ZML-рендер сам сделает small-caps на h1. |
| `summary:` | сгенерируй сам | 1–2 предложения, не более 160 символов. Описывает суть статьи. Если не уверен — оставь пустым: `summary:`. |
| `date:` | из текста исходника (см. §5) | свободный авторский формат: `2 Августа 2021 г.`, `Декабрь 2023`, `08 марта 2024`. Только если действительно нашёл явную «авторскую дату» — иначе **пропусти поле целиком** (не пиши пустое). |

**Что НЕ заполняешь** (это сделает обвязочный python-скрипт):

- `art:` — арт-id статьи в формате `XYZ[n]` (см. SPEC §2.3). Подставит python из `manifest.json` (поле `art`).
- `image:` — cover-картинка из `pics/`. У proza.ru-исходников картинок не было, оператор задаёт вручную если нужно.

## 3. Маркеры ссылок на входе

Python-обвязка `3_transform.py` **до подачи тебе** прогоняет HTML через классификацию ссылок и оставляет только три типа маркеров. Твоя задача — свернуть каждый в ZML-эквивалент.

### 3.1. Внутренняя ссылка (статья yaniktoim-cms)

Вход:
```
⟦INT n="170"⟧Подходящая работа⟦/INT⟧
```

ZML:
```
[[170]]
```

Видимый текст («Подходящая работа») **отбрасывается** — ZML-рендер автоматически подставит заголовок статьи из `manifest.json`. Это намеренно: автор писал разные анкоры на одну и ту же статью, в новой системе они унифицируются.

### 3.2. Zohar-ссылка

Вход:
```
⟦ZOH ch="akdama" n="4"⟧«МИ бара ЭЛЕ» Элияhу⟦/ZOH⟧
```

ZML:
```
{akdama|4}
```

Анкор отбрасывается аналогично — рендер подставит «Книга Зоар. <kniga>. <article>» из `zohar_index.json`.

### 3.3. Внешняя ссылка

Вход:
```
⟦EXT url="https://example.com/page"⟧Подходящая статья⟦/EXT⟧
```

ZML:
```
[https://example.com/page|Подходящая статья]
```

Анкор сохраняется. Если анкор пустой (`⟦EXT url="…"⟧⟦/EXT⟧`) — ZML: `[https://example.com/page]` (без `|`).

### 3.4. Italic-фразы — уже сконвертированы

Python-обвязка `3_transform.py` **до подачи тебе** также прогоняет авторские `[фраза]`-эмфазы через автоконвертацию в ZML-формат `_фраза_` (по правилу word-boundary, см. SPEC §5.6). Когда видишь в подаваемом тексте `_слово_` или `_короткая фраза_` — это уже готовая ZML-разметка для italic-эмфазы (`<em>`). **Ничего с этим не делай**: оставляй как есть в выводе.

Если в подаваемом тексте всё ещё остались авторские `[фраза]` (без `|` внутри, не похожие на ссылку/сноску) — значит pre-conversion на них не сработал (граничный случай). Не пытайся их «починить»: оставь как есть, оператор обработает вручную при post-edit в CMS.

### 3.5. Голых URL быть не должно

Если в подаваемом тексте встретился URL **не в маркере** — это баг обвязки. Не оборачивай его в `[url]` от себя. Оставь как есть в выводе; lossless-валидатор поймает несоответствие и оператор посмотрит вручную.

## 4. Блоки

Блоки отделены друг от друга **пустой строкой** в ZML — так же как и в исходнике.

### 4.1. Параграф (default)

Просто текст без обрамляющих тегов. Может занимать несколько строк подряд, но **без пустых строк внутри** (пустая строка = конец параграфа).

```
Сила в стихах о Сказке, гораздо более реальной, чем то, что мы привыкли называть "жизнь".

О связи духовной Любви и материальной любви.
```

### 4.2. Стих: `[poem]...[/poem]`

```
[poem]
Свет наполнит это Кли[^1]
Трепетной любовью
Ты держи Его внутри
Как свое, родное.

Стих второй строфы
Тоже четыре строки
И последняя
Здесь стоит.
[/poem]
```

- Несколько строф разделены **одной** пустой строкой внутри `[poem]...[/poem]`.
- Каждая строка стиха — отдельная строка ZML; пробелы в начале строки сохраняются (важно для авторской «лесенки»).
- ZML-рендер автоматически капитализирует первую букву каждой строки.

**Опциональный title:**
```
[poem title="Сказка"]
...
[/poem]
```
Заполняй только если в исходнике перед стихом стоит явный заголовок-название стиха (например, «Сказка», «Молитва воина»). Метку **«ЭПИГРАФ»** в стих не превращай — это эпиграф (§4.3).

### 4.3. Эпиграф: `[epi]...[/epi]`

Распознавание эпиграфа в исходнике — следующие маркеры (отдельная строка перед телом эпиграфа, любой регистр):

- `Эпиграф`, `Эпиграф 1`, `Эпиграф первый`
- `Цитата Эпиграф N`
- `ЭПИГРАФ` (голым CAPS отдельной строкой)
- `Песнь Ступеней` — **только если** дальше идёт текст, а не music-блок. Если следом — список треков, это `[mus]` (см. §4.6).

**Что НЕ маркер эпиграфа:**
- `ПРЕДВАРЯЮЩАЯ МОЛИТВА АДАМА` и подобные «название молитвы / песни / трактата» отдельной CAPS-строкой — это **секция `##`**, не эпиграф. Молитва, тропарь, гимн как самостоятельный раздел статьи. Тело молитвы — обычные параграфы (или `[poem]`, если поэтический).

ZML:
```
[epi]
Текст эпиграфа.
[/epi]
```

С указанием автора:
```
[epi cite="К. Кастанеда"]
Воин выбирает свой путь сердца.
[/epi]
```

**Атрибут `cite=` ставится ТОЛЬКО если автор источника указан в той же строке** что и сам текст эпиграфа (в скобках, после тире, в кавычках). Если автор — отдельной строкой ниже текста, **оставь его частью тела эпиграфа** — главное правило «текст 1:1» сильнее красоты атрибута.

Несколько эпиграфов подряд — каждый в собственном `[epi]...[/epi]`. Не объединяй.

### 4.4. Эпилог: `[epil]...[/epil]` *(спящий)*

В текущей коллекции из 350 статей не встречается. Если впервые увидишь явный маркер «Эпилог», «ЭПИЛОГ», «Послесловие» — оборачивай в `[epil]...[/epil]` по аналогии с эпиграфом. Атрибут `cite=` — те же правила.

### 4.5. Цитата: `[quote]...[/quote]`

Маркеры цитаты в исходнике:

1. **Форумная атрибуция** `<Ник> написал(а):` отдельной строкой. Всё, что идёт от этой строки до **первой пустой строки** — тело цитаты. Сама строка-атрибуция в `cite=`:
   ```
   Stalkerdzen написал(а):
   С чего ты взял, что тебя не заберут в психушку?
   
   Реплика (мой ник Сталкер):
   ```
   →
   ```
   [quote cite="Stalkerdzen"]
   С чего ты взял, что тебя не заберут в психушку?
   [/quote]
   ```
   Если после атрибуции идёт **многострочный** ответ (несколько параграфов) — обёртывай только первый параграф до пустой строки.

2. **Явный маркер** «Цитата:» / «Из <источник>:» / длинная цитата другого автора, обособленная отступом или стилем. Если ты её распознаёшь — обертывай. Атрибут `cite="..."` — если известен автор/источник.

Если автор НЕ указан (просто «Цитата:» без имени) — опусти `cite=`. Без явного маркера не угадывай — пусть будет обычный параграф.

### 4.6. Музыка: `[mus]...[/mus]`

Распознавание в исходнике: строка-заголовок «Музыка под настроение», «Песнь Ступеней» (когда после — треки, а не текст), «Рекомендуемая музыка» и аналогичные, **за которой следует один или несколько треков**. Трек = пара `<имя автора/группы> — <название>` со ссылкой (обычно YouTube), либо просто `<автор> — <название>` без ссылки.

ZML:

Default-label («Музыка под настроение»):
```
[mus]
[https://youtu.be/5DBuIhr1Id4|Let Us Burn|Within Temptation]
[https://youtu.be/oAycSf8COQo|Sanitarium|Metallica]
[/mus]
```

Кастомный label (если в исходнике явно «Песнь Ступеней» и т.п.):
```
[mus="Песнь Ступеней"]
[https://youtu.be/abc|Псалом 1|Псалмопевец]
[https://youtu.be/def|Псалом 2|Псалмопевец]
[/mus]
```

Формат строки трека: `[url|title|author]`.
- Все три параметра — **в этом порядке**, разделены `|`.
- Url приходит как `⟦EXT url="..."⟧` — разворачивай в `url` (как сам URL без анкора, в формате трека анкор не передаётся).
- Если в исходнике url нет (без ссылки) — `[|title|author]`.
- Если title пустой (только URL + автор) — `[url||author]`.
- Если автор пустой — `[url|title|]`.
- Если на трек-строку всего одно значение (например, просто YouTube-ссылка без подписи) — заполняй то что есть, остальное оставляй пустым.

**Несколько `[mus]`-блоков в одной статье**: каждое появление «Музыка под настроение» / новой шапки = свой `[mus]...[/mus]`. Если шапка одна, а треков несколько (типичный случай) — всё одним блоком.

### 4.7. Подзаголовок: `[sub]...[/sub]`

В исходнике proza.ru часто первая строка после `<h1>` дублирует заголовок (иногда с inline-сноской). Если ты видишь, что первая значимая строка тела совпадает (или почти совпадает) с `H1` — оборачивай её в `[sub]...[/sub]`. Это поможет рендеру не дублировать заголовок и сохранить inline-сноску.

```
[sub]Летопись Живого Огня[^1][/sub]
```

Если в первой строке нет эха `H1` — `[sub]` не использовать, это обычный параграф.

### 4.8. Нумерованная группа: `[num]...[/num]`

Если автор в исходнике пронумеровал последовательность параграфов сам — например `1.`, `2.`, `3.` (или `1)`, `2)`, `3)`) перед каждым тезисом — оборачивай эту последовательность целиком в `[num]...[/num]` и **удаляй авторские номера** перед каждым пунктом. ZML-рендер поставит «1.», «2.», «3.» автоматически.

Вход (после очистки от HTML):
```
1. Первый тезис.

2. Второй тезис.

3. Третий тезис может быть на несколько строк подряд
в одном пункте.
```

Выход:
```
[num]
Первый тезис.

Второй тезис.

Третий тезис может быть на несколько строк подряд
в одном пункте.
[/num]
```

Условие применения `[num]`:
- ≥ 2 подряд идущих параграфов, каждый явно пронумерован автором в начале (`1.`, `2.`, `3.` или `1)`, `2)`).
- Параграфы разделены пустыми строками.
- Нумерация **последовательна и без пропусков**. Если пропуск (например `1., 2., 4.`) — НЕ оборачивай, оставь как обычные параграфы с сохранёнными номерами в начале.

**Один пронумерованный пункт = не `[num]`**, а обычный параграф с сохранённым номером.

## 5. Colophon: что удалить и куда

В тексте автор часто оставляет служебные строки. Они **не входят** в тело ZML — рендер генерирует их сам из frontmatter. Распознавай и удаляй:

| Шаблон в исходнике | Что делаешь |
|--------------------|-------------|
| `Арт. #AP182` / `Арт.#XX01` / `#XX02` (отдельной строкой или в начале/конце параграфа) | **Удалить полностью.** Авторский арт-номер не сохраняем (у нас свой `id` = NNN из имени файла). |
| `Записано 2 Августа 2021 г.` / `Написано в Декабре 2023` / `Написан 08 марта 2024` | **Извлечь дату** в `frontmatter.date` (формат как в источнике, без «Записано/Написано»). Из тела удалить. |
| Голая дата отдельной строкой: `2 Августа 2021 г.` / `28 февраля 2022 г.` / `22.09.22` | То же — `frontmatter.date`, из тела удалить. |
| `Пост скриптум` / `Примечания` / `Сноски` отдельной строкой перед списком сносок | **Удалить** (в ZML заголовка сносочного блока нет, сноски сами по себе уже размечены `[^N]:`). |

Если в одном параграфе и арт-номер, и дата — удаляй обе сигнатуры, **дату извлеки в frontmatter**, если такой строки нет нигде в теле раньше.

Если арт-номер/дата встречаются **внутри** параграфа (не отдельной строкой) — не удаляй (риск побить текст). Удаление только когда сигнатура — на отдельной строке (или сама составляет весь короткий параграф).

## 6. Сноски

### 6.1. Авторские маркеры в основном тексте

Автор использует разнородные обозначения. Все они конвертируются в `[^N]` (inline-маркер) в порядке появления **в основном тексте**, начиная с 1.

| Автор пишет | ZML |
|-------------|-----|
| `*` (одиночная звёздочка после слова) | `[^N]` |
| `**`, `***`, `****` | `[^N]` (порядковый, не считая звёздочек) |
| `*4`, `*5`, `*9` | `[^N]` |
| `[1]`, `[2]`, `[10]` | `[^N]` |
| `[1.1]`, `[1.2]` | `[^N]` (десятичная часть теряется, для нас просто порядковый N) |
| `[¤ 1]`, `[¤ 11]` (unicode-значки) | `[^N]` |
| `[¶.1]`, `[¶.3]` | `[^N]` |
| `[‡ 1]`, `[‡ 5]` | `[^N]` |
| `[ezer-kenegdo 1]`, `[b-a 7]` (slug + число) | `[^N]` |

Соответствие «авторский маркер → наш N» выводится из порядка появления в основном тексте. Если один и тот же маркер встречается дважды в основном тексте (что бывает — автор иногда ссылается на одну сноску дважды) — используй один и тот же N оба раза.

### 6.2. Тело сноски

В исходнике сноски обычно идут в конце статьи под заголовком «Пост скриптум» / «Примечания» / «Сноски» (заголовок удаляешь, см. §5). Каждая сноска — отдельный блок, начинается с того же авторского маркера (`*`, `[1]`, `[¤ 1]` и т.д.).

ZML:
```
[^1]: Текст сноски.

[^2]: Текст сноски 2.
    Многострочное продолжение с отступом 4 пробела.

[^3]: Стих сноски строка 1
    Стих сноски строка 2

    [[195]]
```

- Один блок = одна сноска. Между сносками — пустая строка.
- Многострочные сноски: continuation-строки начинаются с **4 пробелов**.
- Внутри тела сноски — обычная inline-разметка ZML (`[[nnn]]`, `[url|анкор]`, `{chapter|N}`, `[^M]` если ссылается на другую сноску). Ссылочные маркеры приходят как `⟦INT⟧` / `⟦ZOH⟧` / `⟦EXT⟧` — конвертируй так же как в основном тексте (§3).

### 6.3. Анонимные сноски: «См. также:» без маркера

Если в конце статьи стоит блок типа:

```
См. также:
http://proza.ru/avtor/elia-bm
[[070]] — параллельная работа.
```

— это **анонимные сноски** (footnotes без маркера в основном тексте). В ZML:

```
[^]: [http://proza.ru/avtor/elia-bm|...]
[^]: [[070]] — параллельная работа.
```

Заголовок «См. также:» **удаляется** — рендер сам подставит этот префикс перед каждой анонимной сноской. Если заголовок отличается (например «Дополнение:», «Параллели:» — короткая авторская подпись перед списком), используй `[^|<префикс>]:`:

```
[^|Дополнение]: [[070]] — параллельная работа.
[^|Дополнение]: {akdama|4}
```

Если же в этом списке часть пунктов имеет inline-маркер в основном тексте (т.е. это нормальная сноска), а часть нет (анонимная) — раздели на `[^N]:` и `[^]:` соответственно.

## 7. Секции (h2)

В исходнике автор маркирует подразделы CAPS-строками:
- `АКТ ПЕРВЫЙ. ОБЫЧНЫЙ ПАРАГРАФ И ССЫЛКИ`
- `АКТ ВТОРОЙ. СТИХ С CAPS-ВКЛЮЧЕНИЯМИ`
- `ПОДСТУПАЯ К ТРОПЕ`
- и аналогичные.

Обычно — короткая CAPS-строка, после которой следует пустая и затем тело подраздела. Иногда — без пустой строки, сразу следует параграф.

ZML:
```
## АКТ ПЕРВЫЙ. ОБЫЧНЫЙ ПАРАГРАФ И ССЫЛКИ {akt-1}
```

- Префикс `## ` обязателен.
- Slug в `{...}` — короткий ASCII (`akt-1`, `akt-2`, `podstupaya`, `tropa`, `aliyat-neshama`). Транслитерация из заголовка. **Опционален** — если ты не уверен, опусти `{...}`, рендер сам сгенерирует.
- Текст заголовка — **как в исходнике**, без преобразования регистра. Если автор писал CAPS — оставляй CAPS.

**Что НЕ считать секцией:**
- Лидирующая атрибуция / подзаголовок в самом начале статьи (1–3 коротких строки до первой пустой) — это обычные параграфы, либо `[sub]` если эхо H1.
- CAPS-строки внутри параграфа — это просто CAPS-фраза (small-caps), не секция.
- Метка эпиграфа («Эпиграф», «ЭПИГРАФ», «Песнь Ступеней») — это маркер `[epi]`, не `##`.
- Метка музыки («Музыка под настроение», «Рекомендуемая музыка») — это `[mus]`, не `##`.
- Заголовок «Пост скриптум» — colophon, удаляется (см. §5).

---

## 8. Что НЕ считать стихом

Эти случаи на первый взгляд могут выглядеть как поэзия (короткие строки, переносы), но **не** оборачиваются в `[poem]`:

- **Лидирующая атрибуция в начале статьи** — 1–3 короткие строки до первой пустой строки или явного эпиграфа. Каждая = отдельный параграф (или одна строка-`[sub]` если эхо H1).
- **Colophon-строки** в любом месте — отдельные параграфы (удаляются по §5).
- **Список треков музыки** — `[mus]`, не `[poem]`.
- **Перечислимые тезисы автора** с `1.`, `2.`, `3.` — это `[num]`-группа, не поэзия.

---

## 9. Самопроверка перед выдачей

1. Мысленно убери всю ZML-разметку из своего вывода — `---...---` frontmatter, `## ...` секции, `[poem]/[epi]/[mus]/[num]/[sub]/[/...]` обёртки, `[^N]` маркеры и `[^N]:` тела сносок, развёртки `[[nnn]]` / `{chapter|N}` / `[url|анкор]` — **верни на эти места** соответствующие исходные конструкции (`⟦INT⟧текст⟦/INT⟧` обратно в текст, и т.п.) и авторские сносочные токены (`*`, `[1]`, `[¤ 5]` и т.д. — на места `[^N]`).
2. Удалённый colophon (Арт.#, Записано) — на свои строки.
3. Получившийся текст должен быть **посимвольно идентичен** входному тексту (за исключением входных маркеров `⟦INT⟧/⟦ZOH⟧/⟦EXT⟧`, которые я тебе подал).
4. Если есть расхождение — это баг, поправь.

---

## 10. Формат вывода

- Сначала frontmatter в `---`-обёртке.
- Пустая строка.
- Тело ZML с блоками и секциями.
- Пустая строка.
- Блок сносок (`[^N]:` и/или `[^]:`).
- Никаких ```-обёрток вокруг финального текста.
- Никаких пояснений / комментариев в выводе.

## 11. Минимальный пример

**Вход** (с маркерами от python-обвязки):

```
Заголовок статьи

Подзаголовок один[1]

Текст параграфа со ⟦INT n="170"⟧ссылкой на свою работу⟦/INT⟧ и сноской*.

АКТ ПЕРВЫЙ

Стих первый
Стих второй

Музыка под настроение:
⟦EXT url="https://youtu.be/abc"⟧Within Temptation — Let Us Burn⟦/EXT⟧

Пост скриптум

* Текст первой сноски.

[1] Текст второй сноски — об этом подробнее в ⟦ZOH ch="akdama" n="4"⟧«МИ бара ЭЛЕ» Элияhу⟦/ZOH⟧.

Арт. #AP182, написано 2 Августа 2021 г.
```

**Выход** (ZML):

```
---
title: Заголовок статьи
summary: Краткое содержание статьи в одно-два предложения.
date: 2 Августа 2021 г.
---

[sub]Подзаголовок один[^2][/sub]

Текст параграфа со [[170]] и сноской[^1].

## АКТ ПЕРВЫЙ {akt-1}

[poem]
Стих первый
Стих второй
[/poem]

[mus]
[https://youtu.be/abc||Within Temptation — Let Us Burn]
[/mus]

[^1]: Текст первой сноски.

[^2]: Текст второй сноски — об этом подробнее в {akdama|4}.
```

Замечания по примеру:
- `Арт. #AP182, написано 2 Августа 2021 г.` — последняя строка тела — colophon, **удалён** из тела, дата `2 Августа 2021 г.` → `frontmatter.date`.
- `Пост скриптум` — служебный заголовок сносочного блока, **удалён**.
- `[1]` в основном тексте → `[^2]` (потому что в порядке появления это вторая сноска: первая — `*` в строке про «ссылку на свою работу»). Тело `[1]` тоже становится `[^2]:`.
- `*` в основном тексте → `[^1]`. Тело `*` → `[^1]:`.
- Видимый текст ссылки `«ссылка на свою работу»` отбрасывается — `[[170]]` развёртывается рендером.
- Видимый текст Zohar-ссылки `«МИ бара ЭЛЕ» Элияhу` отбрасывается — рендер подставит сам.
- Music-трек: url, title = пустой, author = «Within Temptation — Let Us Burn» (потому что обозначение слитное в одной строке без явного разделителя «—»; если бы автор написал чётко «Within Temptation — Let Us Burn», лучше попытаться расщепить на title и author по тире, но при сомнении — клади всё в author).
