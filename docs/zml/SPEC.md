# ZML3 — спецификация формата (v3, 2026-06-24)

**Назначение.** Опорная спека ZML3 — источника истины корпуса yaniktoim — для
реализации (`editor/render.js`, `convert/html_to_zml.py`, темы) и CMS-редактора.

**Lineage.** ZML3 — **СВОЯ** спека, НЕ базируется ни на zml1, ни на zml2. Референсные
входы: `cms-revival/zml1/SPEC.md` (базовый набор блоков/inline) и
`cms-revival/zml2/ZML2_SPEC_010.md` (ратифицированная ZML2, 16/16). Развилки разобраны
по одной в `imyavel/roadmap_cms.md` (Статусы 2026-06-09…06-10); вердикты — здесь.

**Состав ZML3 = конструкции ZML2 + 3 осознанных расхождения + 5 новых поверх:**
- **3 расхождения от ZML2:** A1 `caps`-флаг (≠ ZML2 «КАПС литерально»); A2 `notes_title`
  (хранить ≠ ZML2 «выбросить»); A3 orphan-сноска (с номером, без `↑` — уточняет ZML2 Q11).
- **5 новых:** `[spl]` (инлайн-спойлер), ортогональная `width`, `audio:` (🎧-озвучка),
  `[shir]` (блок-грид музыки/«Песнь ступеней»), `[subsec]` (секционный подзаголовок).
- **Добавления fn-ревью (v2, 2026-06-12; 12 вердиктов оператора, реестр =
  `design_review/fn_review_10_progress.md`):** группы сносок `[^имя.N]` + блок `[refs]`/
  `[refs=имя glyph=¤]` (§4.1) · маркеры `[^N]` в `title:`/H1 (§1.2) · уровень `###` (§1.4) ·
  маркер `[toc]`/`[toc collapsed]` (§1.5) · `[line kind=tags|dateline]` (§2.3) · `[ul]`/
  `[ul marker=◆]` (§2.4) · `[epi kind=dedi]` (§2.1) · `[num]` с авторскими номерами и
  скобко-стилем (§2.2) · конвертер-правила лейблов (§2.1, §12). *(FM `dates:` из вердикта 6
  ОТМЕНЁН 2026-06-12 13:59: авторские дата-строки идут `[line kind=dateline]` на своём месте,
  byline всегда рисует manifest-дату; дубль на странице — норма.)*
- **Добавление 2026-06-20:** `[meta]…[/meta]` — карточка-метаданные (proza-шапка
  «Серия/Рассказ/Написано/Формат»): жирные ярлыки + хвостовой `.epi`-дек (§1.3a). Плюс
  атрибут `cite=` у `[epi]`/`[quote]` теперь РЕЗОЛВИТ инлайн (ссылки `[url|текст]`/`[[id]]`/
  `{глава|N}`, сноски `[^N]`), а не экранируется как текст (§2.1).
- Всё остальное — конструкции ZML2 (взяты батчем «всё»): `[epi kind=]`, `[quote
  kind=scripture]`, `[num]`, `[sig]`, `[cry]`, inline `{term|…}`/`{leit|…}`, глифы.

**Статус реализации.** Часть формата уже в `render.js`; часть отложена в «фазу сборки».
Карта — §13. Спека определяет ЦЕЛЕВОЙ формат целиком (включая отложенное).

**Терсность.** Разметка на статью держится на уровне zml1/zml2: почти всё новое —
*необязательные* поля frontmatter и *редкие* блоки. Базовый документ (параграфы + `##` +
`[^N]`/`[^N]:` + `[mus]`) по объёму ≡ zml1.

## 1. Структура документа

```
---
<frontmatter — YAML-подобный; обязат.: title, art; опц. см. §1.1>
---

# <on-page H1>                   ← опц.: авторский заголовок статьи в теле (§1.2)
[sub]<жанровая пометка>[/sub]    ← опц.
[toc]                            ← опц.: маркер TOC на авторском месте (§1.5)

<intro-блоки до первой ##-секции>

## <Заголовок> {slug}
[subsec]<пояснение под заголовком>[/subsec]   ← опц. (§2)
### <Вложенный подзаголовок>     ← опц. (§1.4)
<блоки секции>

[refs=имя]                       ← опц.: вывод группы сносок на авторском месте (§4.1)

[^1]: <тело нумерованной сноски>
[^имя.1]: <тело сноски именованной группы (§4.1)>
[^]:  <тело анонимной сноски>
```

Порядок жёсткий: frontmatter → (`#` H1 + `[sub]`) → intro → `##`-секции → блок сносок в
хвосте (хвост — ФОЛБЭК: группы с явным `[refs]` выводятся на авторском месте, §4.1). Блоки разделяются пустой строкой. art-id, цель `[[art]]`, имя файла `<art>.zml` —
как в zml1 §2.3 (унаследовано).

### 1.1 Frontmatter — поля

| Поле | Обяз. | Деф. | Назначение |
|---|---|---|---|
| `title` | да | — | название статьи (proza.ru); идёт в `<title>`/метадату. Фолбэк видимого H1, если нет `#` (§1.2). |
| `art` | да | — | арт-id (кодирует дату); цель `[[art]]`, имя файла. |
| `zml` | нет | `3` | версия формата. Пишем явно `zml: 3` для самодокументирования. |
| `summary` | нет | «» | мета-описание (`<meta>`), не выводится в теле. |
| `date` | нет | из manifest | дата (ISO `YYYY-MM-DD`; гуманизация — опц. полировка темы). |
| `image` | нет | — | обложка → `<img class="cover" src="../img/<image>">` (канон ZML2 Q10 = B9). |
| `editor`/`edited` | нет | «Иван Иванович»/«» | атрибуция последней правки (§0.6 рендера). |
| `theme` | нет | `A_editorial` | тема оформления (свободный выбор оператора, §8). |
| `width` | нет | `wide` | ширина колонки, **ортогональна теме** (§8): `wide`/`narrow`. |
| `caps` | нет | `off` | **A1**: флаг возрождения zml1-капс (§5). Деф. OFF = КАПС литерально. |
| `notes_title` | нет | «Примечания» | **A2**: авторское имя секции сносок (§4). |
| `audio` | нет | — | **новое**: список аудио-озвучек 🎧 (§7). |
| `dropcap` | нет | `on` | **новое (2026-06-11)**: буквицы темы. Деф. ON (без упоминания); `dropcap: off` гасит — render вешает `.no-dropcap` на `.wrap`, тема (если рисует буквицы, напр. B_manuscript) гейтит свои `::first-letter`-правила `.wrap:not(.no-dropcap)`. Буквица — фича ТЕМЫ (CSS), флаг — лишь per-article выключатель. |
| `allow_faw` | нет | `false` | **новое (2026-06-20)**: включатель вида `[faw]` (§2.5). Деф. **OFF везде** — разметка `[faw]` (`\|`-строки, `[fp]`-пункты) ИНЕРТНА: блок рисуется обычной прозой (но разметка остаётся в `.zml`). `allow_faw: true` + Сохранить → стихотворный вид. |

Опц. поля — per-article: формат обязан их поддерживать, конкретная статья может не иметь.

### 1.2 On-page заголовок `#` (приоритет над manifest — B8 = ZML2 §1.0; усилен 🆔-вердиктом)

- `frontmatter.title` — название с proza.ru, присутствует всегда (метадата, `<title>`).
- `#` в теле — опциональный *отображаемый* H1, часто авторский вариант (нередко КАПС +
  глиф, напр. `# ДАНО ТВОРЦУ … ПРАВО ЛЮБИТЬ <\^/>`).
- **Правило вывода:** видимый H1 = `#` если есть, **иначе** тема берёт `frontmatter.title`.
  Без дублирования (при наличии `#` FM-title как видимый H1 не выводится).
- **Приоритет (ZML3, 🆔):** если у статьи есть свой `#`, ИМЕННО он идёт в `title:` и в H1.
  manifest-title — фолбэк. Конвертер обязан брать H1 первым (не `rec.title or h1`, а
  H1-первым), очищая от 🎧-значков аудио (они → `audio:`, §7).
- КАПС в `#` — по флагу `caps` (§5), как и в `##`.
- **Маркеры сносок в заголовке (fn-ревью, вердикт 2):** `title:` (и `#`) МОЖЕТ нести маркеры
  `[^N]` — позиция значима, конвертер обязан их СОХРАНЯТЬ (24 статьи; 163A/163 — потеря маркера
  делала сноску orphan). Render рисует их в видимом H1 рабочей sup-сноской (sup обязан быть НА
  ГЛАЗ отличим от текста заголовка во всех темах — требование THEME_CONTRACT) и ЧИСТИТ маркеры
  в `<title>`, крошках и prev/next-подписях.

### 1.3 Жанровая пометка `[sub]` и подзаголовок секции `[subsec]`

- `[sub]…[/sub]` — **жанровая пометка** под H1 статьи (авторская строка-эхо: жанр,
  посвящение контексту, «из переписки…»). НЕ структурный подзаголовок — в TOC не входит,
  якоря нет; часть шапки (порядок жёсткий: H1 → byline → `[sub]`). Рендер `h2.subtitle`
  (чисто визуально). Унаследован из zml1; термин «подзаголовок» к `[sub]` не применять —
  вводит в заблуждение (вердикт 21:03 2026-06-12).
- `[subsec]…[/subsec]` — **новое (section-subtitle):** пояснительная строка ПОД
  заголовком `##`-раздела (и концептуально под общим заголовком). Сохраняет авторские
  `<br>`-переносы (построчно) → `<p class="sec-sub">` (приглушённый italic, мельче,
  прижат к `##`; выключка — per-theme). Конвертер мапит `.sec-sub`. В `PAIRED` стоит
  ПЕРЕД `sub` (чтобы `[subsec]` не съелся как `[sub]`).

### 1.3a Карточка метаданных `[meta]` (proza-шапка) — добавлено 2026-06-20

- `[meta]…[/meta]` — **карточка-метаданные**: proza-шапка «Серия/Рассказ/Написано/
  Формат…». Каждая строка `Ярлык: значение` → жирный ярлык (до первого `:`) + значение;
  строки через `<br>` в панели с левым акцентным кантом (`<div class="meta">`; базовый CSS
  `.meta` в шаблоне через `:where()` → 0-специфичность, темы тинтуют/перебивают). Хвостовой
  блок, отделённый ПУСТОЙ строкой, рендерится как `.epi`-дек (курсив под пунктиром) —
  реплика `<span class="epi">` оригинала (1C1). Регистр литеральный (`capsPass:false`);
  сноски/ссылки в значениях резолвятся. Применять там, где оригинал нёс `.meta`-карточку
  (1C1/1AN/1ATA); НЕ для безкарточных чередующихся с эпиграфом `<div class="row">` (1BA).
  В `PAIRED` между `sub` и `sig`.

### 1.4 Секция `##` (обобщена, опц. атрибуты — из ZML2 §1.1)

```
## АКТ ПЕРВЫЙ {akt-1}
## Стих первый {s1} role=chapter
```
- `{slug}` опц. (иначе slugify по тексту, ≤3 слова). КАПС в заголовке — по флагу `caps`.
- `role=` опц.: `preface|epigraph|body|apparatus|colophon|prayer|chapter`; по умолчанию
  деривируется (preface=первая, apparatus=сноски, body=прочее). Кикер/нумерация — тема.
- Рендер добавляет `<a class="back-to-toc">↑</a>` к каждому `##`.
- **`###` — вложенный подзаголовок (fn-ревью, вердикт 4):** h3 И h4 оригиналов мапятся в ОДИН
  уровень `###` (h4 трактуется как последовательный брат h3; если это уродует структуру —
  конвертер ставит флаг). TOC рисует `###` вложенным вторым уровнем. NB: poemsub (подзаголовок
  поэмы, напр. 239 «Dream On…») — НЕ заголовок → `[subsec]`/poem-title.

### 1.5 Маркер `[toc]` (fn-ревью, вердикт 11)

- TOC рисуется ТОЛЬКО по явному маркеру `[toc]` в теле, на авторском месте. Без маркера TOC
  не рисуется (фикс-слот рендера убирается).
- Конвертер ставит `[toc]` только у статей, где TOC был в живой вёрстке (74 из 352; остальные
  278 остаются без TOC — фиксируем первоначальное LLM-решение).
- Дефолт — раскрытый; `[toc collapsed]` — свёрнутый (1 статья корпуса).
- `[toc nonum]` — гасит авто-нумерацию `<ol>` оглавления (класс `.article-toc.nonum`): нужен,
  когда заголовки уже несут свои числа («1 / 1.1 / 1.1.1»), иначе двойная нумерация. Флаги
  сочетаются: `[toc collapsed nonum]`.
- Порядок шапки НЕ меняется: H1 → byline → `[sub]`; маркер чинит только клин TOC.
- TOC включает `##` и вложенные `###` (вторым уровнем).

### 2.6 `[dlg]…[/dlg]` — диалог: детектор спикеров (реализация `render.js::renderDialog`)

Содержимое `[dlg]` — реплики ОБЫЧНЫМИ абзацами (пустая строка между). Рендер относит каждый
абзац к спикеру по ВЕДУЩЕЙ МЕТКЕ и собирает «посты»; вывод —

```
<div class="dialog">
  <div class="post"><span class="post-by">МЕТКА</span><span class="post-text">…тело…</span>…</div>
  <p class="dlg-line">…безметочный лид…</p>
</div>
```

- **пост** = метка + одно/несколько `<span class="post-text">` (впитанные тела);
- **`p.dlg-line`** — абзац без метки ДО первого спикера (лид-капшен «Диалог на форуме…»).

**Определение метки — два ВЗАИМОИСКЛЮЧАЮЩИХ пути на блок:**

1. **Явный маркер `>> Метка`** в начале абзаца. Если в блоке есть ХОТЯ БЫ ОДИН абзац,
   начинающийся на `>> ` — ВЕСЬ блок идёт явным путём (эвристика отключается). Метка = текст
   от `>> ` до первого `\n`; остаток абзаца — первое тело поста. **Канонический способ**
   (надёжен, не зависит от пунктуации; см. фикс 14N: `Вопрос`/`Ответ` → `>> Вопрос`/`>> Ответ`).
2. **Эвристика `splitSpeaker`** (только если в блоке НЕТ ни одного `>>`): метка распознаётся
   в начале абзаца тремя паттернами в порядке проверки —
   - `Ник написал(а):` — форум-тред (имя ≤40 симв., далее ` написал(а)` + опц. `:`);
   - `Вопрос:` / `Ответ:` — Q&A (слово `Вопрос`|`Ответ`, затем `:` ИЛИ `.` — **разделитель
     обязателен**: `Вопрос 1`, `Ответ Мир`, `ВопросВ` НЕ распознаются);
   - `Имя:` — короткое имя одним токеном (заглавная + ≤23 не-пробельных-не-`:` симв. + `:` +
     пробел + непустой текст).
   Не совпало ни одно → абзац без метки.

**Впитывание.** Абзац с меткой открывает новый пост. Следующие абзацы БЕЗ метки впитываются
телами в ТЕКУЩИЙ пост (реплика многоабзацна). Абзац без метки и без открытого поста → `p.dlg-line`.

**Инертность (важно).** Если НИ ОДИН абзац блока не дал метки (нет `>>`, эвристика молчит —
тире-диалоги `— реплика`, голые подписи, не-диалоги) — `[dlg]` НЕ даёт ни одного `.post`: весь
контент рисуется `p.dlg-line` внутри `div.dialog`, **визуально неотличимо от прозы** (темы
`.dlg-line` пока не стилизуют). Такой `[dlg]` фактически инертен → размечать `>> Метка` либо
снять тег. Тема МОЖЕТ стилизовать `.dialog/.post/.post-by/.post-text` (эталон — форум ccastaneda.ru).

**Конвертер** собирает ран соседних диалог-узлов оригинала (p.speaker×N, section.question/answer,
div.dialog/dialogue/qa) в один `[dlg]`; не-абзацные блоки внутри → фолбэк-проза с флагом.

### 2.1 `[epi]` — функция, не цитатность (A4+B5 = ZML2 Q3 + 📐-вердикт)

- `[epi]` = единый блок-РОЛЬ «обрамление» (предваряет / сопровождает / завершает). Функция,
  не цитатность: содержимое — своя проза/стих/афоризм автора ИЛИ внешняя цитата (`cite=`).
- **Ось `kind=prose|verse|aphorism`** (деф. `prose`):
  - `prose` — абзацы (мягкие переносы схлопываются);
  - `verse` — стих: переносы строк СОХРАНЯЮТСЯ, рисуются построчно (`<br>`), пустая строка =
    разрыв строфы (`<p>`); класс `.epigraph.verse`. Чинит баг склейки стих-эпиграфа;
  - `aphorism` — короткая standalone-сентенция;
  - `dedi` — **новое (fn-ревью, вердикт 8):** посвящение (класс `.dedication` оригиналов).
  Тема рисует подвиды по-своему (form-agnostic).
- **Эпилог — БЕЗ отдельного тега `[epil]` (A4):** эпилог = `[epi]` в ХВОСТОВОЙ позиции
  (последний блок перед аппаратом сносок); метку «Эпилог» (vs «Эпиграф») ставит рендер по
  позиции. → render: убрать `epil` из `PAIRED`, добавить детект хвоста в `renderEpigraph`
  (см. §13, отложено).
- Конвертер: `kind` эвристикой (стих-форма `<br>`-строк → `verse`; короткая сентенция → опц.
  `aphorism`; иначе `prose`), при `verse` хранит переносы. Оператор переопределяет в редакторе.
- **Конвертер-правила (fn-ревью):** заголовок/лейбл «ЭПИГРАФ» → содержимое уходит в `[epi]`,
  лейбл СНИМАЕТСЯ (вердикт 9; 35 статей, в т.ч. 6 сейчас вовсе без [epi]:
  16J/18K/1CI/2CQ/341A/571; постатейная проверка после прогона, спорные — оператору;
  стих-эпиграфы → `[epi kind=verse]`) · `.coda` → хвостовой `[epi]` (обрамление-эпилог) ·
  `.dedication` → `[epi kind=dedi]` · label-спан «Цитата» у blockquote снимается (§12).

### 2.2 `[num]` — авторские номера и скобко-стиль (fn-ревью, вердикт 7)

- `[num]` держит АВТОРСКИЕ номера единиц (НЕ перенумеровывает; дыры/повторы — как у автора) и
  их скобко-стиль: «1.» или «1)». Стиль маркера — механика `--marker` → `li::marker`.
- **`[num kind=toc]` (оператор, 2026-06-12 15:00):** пункты блока получают якоря и входят в
  TOC своими номерами («1.», «2.»…) на документном месте — «нумерованный список абзацев как
  список оглавления». **Опция РУЧНАЯ, по умолчанию ВЫКЛ (15:08)** — конвертер её НЕ ставит;
  включается минимальной правкой тега в источнике (кейс-мотиватор: 16J, чей рукотворный TOC
  ссылался на номерные секции-якоря).
  **Опц. префикс TOC-метки (15:04): `kind=toc|Пункт`** → в оглавлении «Пункт 1», «Пункт 2»…
  (БЕЗ точки/скобки на конце — 15:06); без префикса — голые «1.», «2.»… (префикс с пробелами —
  в кавычках: `kind="toc|Мой пункт"`).
- Конвертер мапит висячую ручную нумерацию `span.n`/`span.num` В ТЕЛЕ статьи → `[num]`
  (163A/18HB/221B/1BI/1B3/273A/24I + 185A-семья). **`.num` в сносочных списках НЕ трогать** —
  чек после прогона: общее число сносок корпуса до/после не регрессировало.
- **Многоабзацный пункт.** Пункт может содержать НЕСКОЛЬКО абзацев (пустая строка внутри пункта,
  06I п.2) — render парсит тело пункта через `parseMain`, и пустая строка даёт отдельный `<p>`
  (а не схлопывается в `<br>`). Одноабзацные пункты идут прежним путём (zero-regress).
- **Богатый пункт (вложенный блок).** Тело пункта может НЕСТИ вложенный блок (`[epi]`/`[quote]`/
  `[mus]`/… — 35Q пп. 1,2 эпиграф/цитата, 4,5 плееры): маркер вложенности — открывающий тег в
  теле; `<li class="num-rich">`. Для вложенного `[mus]` номер пункта служит этикеткой → плашка
  «Музыка под настроение» гасится.

### 2.3 `[line kind=…]` — служебные роль-строки (fn-ревью, вердикт 8)

- `[line kind=tags]…[/line]` — теги-цепочка («Будущий мир·Круг Жизни·…»);
  `[line kind=dateline]…[/line]` — дата-строка («Написано: Понедельник, 15 Февраля 2021 г.»).
  **ВСЕ авторские дата-строки** (шапочные киккер-даты, `.date`, `.dateline`, диапазоны 163A) —
  сюда, на своё место в теле; inline-резолв работает (маркеры сносок/ссылки в дата-строке живут).
  Byline при этом всегда рисует manifest-дату — дубль допустим (решение 2026-06-12 13:59).
- Список `kind` ЗАКРЫТЫЙ: `tags|dateline`. Render → `p.line.line-<kind>`; `[line]` ИСКЛЮЧЁН
  из буквица-цепочек (dropcap).
- Конвертер мапит ПО КЛАССАМ оригинала: `.tags` → `tags`, `.dateline`/`.secmeta` → `dateline`.
  Голые строки без класса (1CM) остаются прозой. Соседние роли-строки: `.closing`/`.banner` →
  `[cry]` (существующий), `.coda`/`.dedication` → `[epi]` (§2.1).

### 2.4 `[ul]` — маркированный список (fn-ревью, вердикт 12)

- Пункты — строки, начинающиеся «- ». Без атрибута — дефолтный значок темы;
  `[ul marker=◆]` меняет ТОЛЬКО значок (механика как у `[num]`: `--marker` → `li::marker`).
- Диалоги — НЕ списки: выходят прозой-тире (норма типографики; спот-чек ~70 флагов).

### 2.5 `[faw]` — free-associative writing (стихи, записанные прозой) (новое, 2026-06-20)

**Включатель `allow_faw` (frontmatter, деф. `false` ВЕЗДЕ).** Стихотворный вид `[faw]`
рисуется ТОЛЬКО при `allow_faw: true`. По умолчанию (нет поля или `false`) разметка `[faw]`
инертна: блок рисуется ОБЫЧНОЙ ПРОЗОЙ (`renderFawInert`) — `\|`-границы строк склеиваются
через пробел, `[fp]`-пункты остаются разрывом абзаца + бейдж + запись в TOC (структура/
оглавление сохраняются), стиховая верстка/чередование/капитализация не применяются. Сама
разметка `\|`/`[fp]` ОСТАЁТСЯ в `.zml` — оператор включает вид флагом `allow_faw: true` +
Сохранить (авто-разметка на Сохранить работает независимо от флага: `\|` проставляются всегда).

Часть корпуса — это **стихи, записанные сплошной прозой подряд**, но выдержанные во
внутреннем размере (счёт слогов и/или рифма). `[faw]…[/faw]` помечает такой блок, чтобы
(а) границы стихотворных строк можно было показать на глаз и (б) текст читался как стихи,
оставаясь визуально монолитным там, где это уместно дизайну.

- **Разметка строк — знаком «\|».** Граница каждой найденной строки обозначается «\|»
  (на ВЕРХНЕМ уровне — «\|» внутри `[url\|анкор]` и прочих `[…]` не разделитель). Блок
  считается *размеченным*, если есть хотя бы один верхнеуровневый «\|».
- **Авто-разметка при «Сохранить».** Если внутри `[faw]` НЕТ ни одного «\|» — это указание
  движку: ПЕРЕД сохранением ZML (кнопка «Сохранить» в редакторе) разметить содержимое
  алгоритмом счёта слогов и проставить «\|» между строками. Алгоритм — порт инструмента
  `Documents/verse_tool/verse_split_003.py` → `editor/verse_split.js`; его параметры (словарь
  чтения `dict_common.txt` + ручные правки `ovr_common.txt`) вшиты константами в модуль
  (источник истины — те .txt). Размер строки определяется автоматически (перебор 5–14 слогов);
  необязательный `meter=N` на теге фиксирует размер. Хук — `editor/faw_markup.js::autoMarkupFaw`,
  подключён в `ze-core` как `opts.preprocess` (ya-edit / ya-struct). Идемпотентно: уже
  размеченный блок («\|» есть) не трогается. JS-порт сверен с Python байт-в-байт (61H: размер 8,
  924 строки; самотест — `editor/_faw_test/`).
- **Рендер (render.js `renderFaw`).** `inner` делится по верхнеуровневым «\|» на сегменты-строки;
  каждый — `<span class="faw-l a|b">` (чередование a/b по индексу), inline-резолв сегмента —
  обычный (`[^N]`, `_курсив_`, ссылки работают). Обёртка — `<div class="faw">`. Счёт слогов в
  рендере НЕ повторяется — он опирается только на «\|».
- **Вид по темам (THEME_CONTRACT).** Чередование двух стилей делает границы строк различимыми;
  режим задаёт ТЕМА: **монолит** (`.faw-l{display:inline}` — текст течёт прозой, границы видны
  чередованием) в **swiss / A_editorial / cyberpunk**; **построчно** (`.faw-l{display:block}`)
  в **B_manuscript / ar_deco**. База шаблона — только отступ блока и фолбэк `:where(.faw-l)`
  (нулевая специфичность, тема перебивает; `<style>` идёт после `<link>` темы).
- **Капитализация строк (только построчные темы).** При РАЗБИЕНИИ на строки каждая строка
  начинается с заглавной буквы (как принято в стихах). Реализация: render оборачивает первую
  БУКВУ каждого сегмента в `<span class="faw-cap">` (PUA-сентинелы на сыром тексте до inline-резолва
  → корректно пропускают ведущую пунктуацию/тире/markup, напр. «- не» → «- Не», и не цепляют
  html-сущности); построчные темы (`B_manuscript`/`ar_deco`) поднимают `.faw-cap` в верхний регистр,
  монолитные — НЕ трогают (проза в авторском регистре).
- **`sta=N` — размер строфы (stanza).** `[faw sta=5]` — каждые N строк отделяются пустой строкой:
  render вешает класс `.faw-se` на каждую N-ю строку, построчные темы дают ей `margin-bottom`.
  В монолитном режиме параметр ИГНОРИРУЕТСЯ (верт. margin к inline не применяется). `meter=`/`sta=`
  сочетаются. Оба — необязательные атрибуты на теге.
- **Нумерованные пункты сквозь строки (раздел-маркеры).** Если прозо-стих разбит на
  нумерованные пункты (как 61H: `## 1..7` в оглавлении), а стихотворные строки ПЕРЕТЕКАЮТ
  через границы пунктов — пункты живут ВНУТРИ одного `[faw]` как маркеры, которые НЕ рвут
  строку. Автор пишет границу строкой `=== <label> {slug} ===` (стиль verse_tool); при
  «Сохранить» движок (markupFaw) разрезает ВЕСЬ поток разом (строки текут через границы) и
  ставит инлайн-маркер `[fp="<label>" slug="<slug>"]` ПЕРЕД словом, где пункт начинается
  (часто в середине строки). render (`renderFawSegment`) рисует `[fp]` бейджем `.faw-pt`
  (id-якорь) и добавляет запись в TOC (уровень 2 — как `##`, которые маркер заменяет);
  `[toc]` в шапке нужен, чтобы оглавление рисовалось. Идемпотентно (есть «\|» → не
  размечаем; `=== ===` уже свёрнуты в `[fp]`).
- **Безымянные абзацы (без нумерации).** Если у прозо-стиха просто абзацы (без нумерации/TOC,
  как 61T), их границы пишутся ПУСТОЙ СТРОКОЙ внутри `[faw]`; markupFaw ставит на их месте
  `[fp]` БЕЗ метки. render: безымянный `[fp]` в начале строки начинает новый **абзац-блок
  `.faw-p`** — и в инертном виде (новый `<p>`, без бейджа/TOC), и в стихе (allow_faw ON):
  между абзацами есть отступ (`.faw-p + .faw-p`), видимый и в монолитных темах, и в построчных;
  ВНУТРИ абзаца стих течёт/ломается по теме. Так 61T сохраняет свои 6 абзацев в ОБОИХ видах.
  (Нумерованные `[fp="N"]` абзац НЕ начинают — текут сквозь строки, см. выше.)
- **Семантика `\n`.** Внутри `[faw]` единственный разделитель строк — «\|»; авторские `\n`
  нормализуются в пробелы (блок — единый поток). Это явное исключение из §9 для данной
  конструкции.

## 3. Inline-конструкции

Порядок парсинга (как ZML2 §3): `[^N]` → `[[art]]` → `{chapter|N}` → `{term|…}`/`{leit|…}` →
`[url|анкор]` → `_italic_` → (CAPS-pass по флагу, §5) → `[spl]`.

| Конструкция | Семантика |
|---|---|
| **`[^N]` / `[^имя.N]`** | маркер сноски → `<sup>` + popup; `[^имя.N]` — именованная группа (§4.1). Повтор `[^N]` → `cite_ref-N-extraK`. |
| **`[[art]]`** | внутр. ссылка; заголовок из manifest (без `\|`-якоря — B6/ZML2 §9). |
| **`{chapter\|N}`** | ссылка на Зоар; заголовок из `zohar_index`. Глава и номер **необязательны**: `{глава\|}` — ссылка на ВСЮ главу (её index-страница `…/глава/`), `{\|}` — на ВЕСЬ Зоар (корневой index = полное оглавление). Якоря: статья → «Книга Зоар. <книга>. <статья>», глава → «… <книга>. <глава>», корень → «Книга Зоар». |
| **`{term\|текст}` / `{leit\|текст}`** | опц. инлайн-крючок термина/лейтмотива (C10/ZML2 Q13); тема красит или игнорирует. |
| **`[url\|анкор]` / `[url]`** | внешняя ссылка (голые URL запрещены в теле). |
| **`_фраза_`** | italic-эмфаза (1–60 симв, на границах слов). |
| **`[spl]…[/spl]` / `[spl="cover.gif"]…`** | **новое:** инлайн-спойлер (Телеграм-стиль): контент под обложкой-`::before` (деф. shimmer / gif), клик раскрывает (JS шаблона). Резолвится ПОСЛЕДНИМ (внутренний текст уже прошёл все пассы); работает внутри `[sub]` и любых блоков. |

**Глифы (C13/ZML2 §5):** распознанные авторские глифы → `<span class="glyph">` (тема красит,
manuscript золотит). Whitelist рендера (расширяемый): парные `<\^/>` (руки вверх) / `</v\>`
(руки вниз); эмотиконы `:)`, `;::)))` и т.п. Парсер их не интерпретирует. **НЕ путать с мусором
proza.ru:** последовательности ≥2 `;` (`;;;;`, ивр. `;;; ;;;;`) — артефакт импорта, чистятся
при адаптации (§12), в `.glyph` не оборачиваются. (Отложено в фазу сборки, §13.)

## 4. Сноски

`[^N]:` нумерованная (continuation = отступ 4 пробела → `<br>`) · `[^*]:`/`[^**]:`/`[^***]:`
**звёздная** (авторский ✱-маркер; ПЕРВОКЛАССНАЯ: маркер `[^*]` в теле кликабелен → определение,
у определения backref-`↑`; id = `star<кол-во звёзд>`; добавлено 2026-06-12, источник — схема 182)
· `[^]:` анонимная («См. также:») · `[^|преф]:` анонимная с кастомным префиксом (чисто-звёздный
префикс трактуется как звёздная сноска). Нумерованные первыми, анонимные после. Секция сносок
начинается с первой строки `[^…]:`.

- Заголовок секции — `notes_title` из frontmatter (**A2**, деф. «Примечания»). Конвертер
  извлекает авторское имя notes-секции в это поле И НЕ эмитит его как `##` (иначе дубль).
  render рисует `notes_title` вместо хардкода «Примечания» (см. §13, отложено).
- `kind` (ref/extended/term), `fn-wide` — ДЕРИВ рендером/CSS.
- `sourceType`-маркеры (`Музыка::`, `Цитата::`) — ЛИТЕРАЛЬНО в теле (автор так пишет; `::`
  НЕ трогаем огульно, см. §12 / B6).
- **orphan (A3):** определение без `[^N]`-маркера в тексте СОХРАНЯЕТ номер (`[^4]:`, верно
  источнику), но рендер НЕ печатает backref-`↑` (возвращаться некуда). Реализация: реестр
  `inline.refNotes` (id всех упомянутых `[^N]` из тела и тел сносок); orphan = вне реестра →
  без стрелки. Это уточняет ZML2 Q11 (там — анон-карточка без номера): ZML3 номер сохраняет.

### 4.1 Группы сносок и `[refs]` (fn-ревью, вердикты 1+3+5; а-ля MediaWiki)

Чинит пер-секционные схемы сносок (12F/1CM/217A/341A): кражу notes_title, опустошённые
секции-скелеты, авторский порядок секций.

- **Дефолт-группа** — `[^N]`/`[^*]`/`[^]` — БЕЗ ИЗМЕНЕНИЙ (всё в §4 выше).
- **Именованная группа:** маркер в теле — `[^имя.N]`, определение — `[^имя.N]: …`.
  id определения — `cite_note-имя-N` (дефолт-группа: как сейчас).
- **Вывод группы — блок `[refs=имя]`** на АВТОРСКОМ месте документа; `[refs]` без имени =
  дефолт-группа. Заголовок блока render НЕ генерит — это обычный `##`/`###` НАД маркером.
  Позиция `[refs]` и задаёт авторский порядок секций (вердикт 5: render больше не форсит
  «сноски последними»).
- **Фолбэк:** группы (и дефолт-сноски) без своего `[refs]` выводятся хвостом документа с
  заголовком `notes_title` (поведение §4 как раньше).
- **`glyph=` (вердикт 3):** `[refs=имя glyph=¤]` — авторский значок серии; маркеры группы
  рисуются «¤1, ¤2…» (и в теле, и в списке). Серии корпуса: 1CM ¤ ¶ ^ ‡; 341A `*N`;
  юникод-звёзды (∗ U+2217 и др.) распознаются как звёздные маркеры (239 `∗∗∗`).
- **Orphan внутри группы** — по A3: номер сохраняется, backref-`↑` нет.
- **Сиротский `[refs=x]`** (нет ни одного определения группы x) — флаг конвертера/рендера,
  блок не рисуется.

### 4.2 Трек-плеер как цель сноски — `[mus refs=имя glyph=¶]` (вердикт 14:13 2026-06-13)

Часть авторских «сносок» — это ССЫЛКИ НА МУЗЫКАЛЬНЫЕ ТРЕКИ: маркер в тексте ведёт не на
текстовое примечание, а на плеер рекомендованной песни (1CM серия `¶`, 12F «Рекомендуемая
музыка», 3B7 серия `♪`). Конструкт связывает [mus] с системой сносок:

- **`[mus refs=имя glyph=g]`** — музыкальный блок, чьи треки суть ОПРЕДЕЛЕНИЯ сносок группы
  `имя`. Строка трека получает 4-е поле: `[url|title|author|N]`, где `N` — номер сноски.
- **Маркер** в тексте — `[^имя.N]` (как у именованной группы §4.1), но целит на ПЛЕЕР:
  render даёт `<sup id=cite_ref-имя-N><a href="#cite_note-имя-N">` с меткой `glyph`+N
  (`¶1`/`♪4`) или `[N]` без глифа.
- **Трек-цель** получает `id="cite_note-имя-N"` и обратную стрелку `↑` к маркеру (если на
  него ссылаются). Плеер сохраняется — определение и есть сам трек, отдельного текстового
  определения `[^имя.N]:` и блока `[refs=имя]` НЕТ.
- **Конвертер:** пре-проход `register_music_footnotes` (ДО `collect_footnotes`) находит
  `<a href="#trackid">` на трек-узлы (`is_track` c `id`), регистрирует `FN_ID_MAP[trackid]=
  имя.N` по префиксу/номеру id. Запуск ДО collect нужен, чтобы (1) резолвить маркеры внутри
  ТЕЛ сносок, (2) дать collect ПЕРЕЗАПИСАТЬ id, если трек на самом деле обычная сноска
  (`id=fn-N` + `is_track` — тогда трек НЕ становится плеером-целью).

## 5. CAPS и глифы

**A1 — `caps`-флаг (frontmatter, деф. OFF).** Расхождение с ZML2 (там КАПС литерально
безусловно) — осознанное.
- `caps: off` (**дефолт**) — КАПС рендерится КАК ЕСТЬ, без фолдинга/списка имён/`^`-маркера.
  `^` теряет спец-значение (кроме синтаксиса сноски `[^N]`).
- `caps: on` — возрождает ВСЁ zml1-поведение: КАПС-строка (≥70% прописных, ≥3 букв) →
  `<span class="sb">` (small-caps/болд — на усмотрение темы); список `proper-nouns.txt` держит
  имена заглавными (склонения по падежам); ручной `^Слово` форсит заглавную; капитализация по
  предложениям; honorific «Свят Благословен Он» как единица.
- **Реализация (СДЕЛАНО):** `render.js` гейтит CAPS-пасс флагом — `resolveInline` зовёт
  `resolveCaps` только при `capsEnabled` (из `fm.caps`; truthy = `on/true/1/yes/да`, деф. OFF).
  Список `proper-nouns.txt` подаётся через `ctx.properNouns` (освежать из живого корпуса).

**Глифы** — см. §3 (whitelist + чистка мусора proza.ru).

## 6. Блок `[shir]` — грид музыкальных плиток («Песнь ступеней» + mood-music)

Новый общекорпусный блок ZML3. Разобран по 8 пунктам (roadmap 🎼, 2026-06-10).

### 6.1 Сущность и контексты
`[shir]` — **общий переиспользуемый контейнер-грид**, два контекста:
- **(a) спец-страница «Песнь ступеней»** — плитки + ПОД каждой список статей, где музыка
  упоминается (этот список — роль контекста (a));
- **(b) внутри обычной статьи — «Музыка под настроение»** — тот же плиточный грид с
  фреймами для нескольких музыкальных вставок подряд, БЕЗ списка статей. **Контекст (b) в
  активном корпусе отсутствует** → формат его ДОПУСКАЕТ, реализацию/миграцию не делаем сейчас.
  (NB: позже сверить с `[mus]` — реконсиляция отложена.)

### 6.2 Структура и синтаксис (line-based)
`[shir …]` — контейнер-грид (один на страницу/раздел). **Отдельной песни своего тега НЕТ:**
песня = ОДНА СТРОКА внутри контейнера. Колонки через `|`:

```
[shir cols=3 min=300]
<ytID> | <Композиция> | <Автор> | <id, id, id>
dQw4w9WgXcQ | Песнь восхождения | Шломо Карлебах | 03H, roza_mira
xY12abc7890 | Другая песнь | Автор | 17DA:П-е-с-н-ь, 03H
[/shir]
```
- **YouTube-ID** — чистый, без `?si` (см. roadmap [[feedback_yaniktoim_youtube_no_si]]).
- **Композиция и Автор** — РАЗДЕЛЬНЫЕ колонки (НЕ пред-склеивать `—`; render склеивает
  «Композиция — Автор»).
- **4-я колонка — список статей** по внутр. арт-id через запятую; reuse `[[art]]`-резолва
  (title+href из manifest → авто-синк, уходит хардкод). **Per-id override-подпись** ссылки —
  `id:Текст` (для стилизованных подписей типа «П-е-с-н-ь C-т-у-п-е-н-е-й»). **Колонка
  необязательна** (может быть пустой/отсутствовать) — для контекста (b).
- Редкий `|` внутри поля экранируется `\|`.

### 6.3 Валидность и локализация ошибки
- Запись валидна при ОБЯЗАТЕЛЬНЫХ трёх полях — **ytID + Композиция + Автор**. Список статей —
  НЕОБЯЗАТЕЛЬНЫЙ (0 допускается; в (a) обычно есть, в (b) нет). Правило едино для (a)/(b).
  **Реализация (2026-06-18):** ОБЯЗАТЕЛЬНЫ ytID+Композиция; автор — рендер ГРАЦИОЗНО терпит пустого
  → comp-only (safety-net, не error; консистентно с `[mus]` и контекстом (b)). На странице songs
  у всех 220 автор проставлен (17 безавторных дозаполнены резолвом YouTube) — нарушений нет.
- **Битая строка** (нет любого из трёх) роняет ТОЛЬКО свою плитку, НЕ весь блок. Рендер/
  конвертер обязан дать точный диагноз (№ строки в блоке + её текст + какого поля нет); в
  режиме отладки — рисовать на МЕСТЕ плитки видимый маркер-заглушку («⚠ строка N: нет автора»),
  чтобы ошибка была видна на странице (важно в ~220-строчном блоке).

### 6.4 Опции раскладки (атрибуты на теге `[shir …]`)
- `cols` = МАКС число плиток в ряд (деф. `3`); `min` = мин. ширина плитки (деф. `≈300px`).
- Адаптив через CSS-грид `auto-fill + minmax(max(min, (100%−gaps)/cols), 1fr)` — без
  хардкод-медиазапросов: на узком сам отдаёт колонки.
- Опции живут НА ТЕГЕ (не frontmatter) — локально, допускает несколько гридов в одной статье.

### 6.5 Проигрыватель (как на нынешней опубликованной странице, без нового)
Lazy-YouTube 1:1: превью `i.ytimg.com/vi/<ID>/hqdefault.jpg`, `.play`-оверлей, клик → впрыск
`iframe` autoplay; a11y (`role=button`/`tabindex`/Enter/Space/`aria-label`). **Lazy
обязателен** (220 iframe сразу = смерть страницы). Механика фиксирована в render/template; вид
плитки — тема (§6.7).

### 6.6 Заголовок блока
`[shir]` рисует ТОЛЬКО грид. Заголовок «Песнь ступеней» и описание идут ОТДЕЛЬНО сверху:
заголовок = обычный `##`, описание = обычный абзац/`[subsec]` над блоком (как на текущей
странице: заголовок → описание → плитки).

### 6.7 Тематизация (5 дизайнов)
Компонент `[shir]`+плитка добавляется в `THEME_CONTRACT.md`; каждая из 5 тем (A/B/cyberpunk/
swiss/ar-deco) оформляет плитку ПО АНАЛОГИИ со своим существующим дизайном (форма карточки,
play-кнопка, разделитель-глиф, типографика подписи). Дизайн-намерение — сейчас; CSS-реализация —
в отложенной фазе (§13).

### 6.8 Носитель и фаза реализации
Блок-формат `[shir]` фиксируется ЗДЕСЬ сейчас. Парсер/render/CSS-темизация + отладка + миграция
спец-страницы songs (ZML-носитель `docs/songs/index.zml`?) — на ПОСЛЕДНЕМ этапе, ПЕРЕД
редактируемыми разделами (Ф10). songs — спец-страница, не арт-id-статья.

## 8. Тема и ширина (ортогональны)

- **`theme`** — свободный выбор оператора на статью (в редакторе переключателем). LLM-привязка
  при миграции = лишь стартовый дефолт (ближайший фингерпринт), переопределяется в любой момент.
  5 тем (Ф1): `A_editorial`, `B_manuscript`, `cyberpunk`, `swiss`, `ar_deco`.
- **`width`** — ОТДЕЛЬНОЕ поле, ОРТОГОНАЛЬНОЕ теме: `wide` (~1080) / `narrow` (~820). Набор из

  `.w-narrow`). Гарантия качества — тема при РОДНОЙ ширине; при смене — обязана не ломаться.
- Два независимых рычага на статью: ширина × тема. Дефолты: `A_editorial`, `wide`.

**Контракт тем** — `cms-revival/themes/THEME_CONTRACT.md` (полное покрытие классов render.js).

## 9. Семантика переносов строк (`\n`): значим ВЕЗДЕ

**Глобальный инвариант (решение оператора 2026-06-12 14:25): в корпусе НИЧЕГО не плющится
само.** Каждый `\n` в `.zml` — авторский перенос, и render рисует его реальным переносом
(`<br>`) во ВСЕХ блоках: проза, `[quote]`, `[epi]` любого kind, `[num]`, `[poem]`, `[subsec]`,
`[sig]`/`[cry]`, continuation сносок. Пустая строка = разрыв абзаца/единицы. Деление
verse/prose — ТОЛЬКО стилевое (какой обёрткой/классом рендерить), оно никогда не решает
судьбу строк. Прежняя таблица significant/flow упразднена.

**Converter-требование:** конвертер обязан (а) схлопывать ТОЛЬКО косметический whitespace
разметки (pretty-print `\n`+отступы; отделяется BR-сентинелом от авторских `<br>`),
(б) сохранять авторские `<br>`/построчные спаны как `\n` ВО ВСЕХ блоках без эвристик.
Исключения возможны только по ЯВНОМУ правилу оператора (на 2026-06-12 таких нет; однострочные
по своей природе поля — заголовки `##`, `[line]`, поля трека `[mus]` — фиксируются здесь как
номинально однострочные).

## 12. Authoring-guidance для адаптирующей LLM (из ZML2 §8, наследуется)

- **Лейтмотивы/термины** (`term/leit`): метить редкие осмысленные; НЕ метить высокочастотные
  доксологии («Свят Благословен Он»). Смысловое решение, не авто-детекция.
- **Сверхдлинные абзацы:** переносить «как есть», не дробить.
- **Голые URL:** оборачивать в `[url|анкор]`/`[[art]]`/`{chapter|N}`/трек `[mus]`.
- **Ссылки-по-id не дублировать заголовком:** `[[ID]]` и `{chapter|N}` подставляют название
  сами. Канон см.-также (B6): `См. также: [[ID]] — Автор` (конвертер по заголовку ищет art-id;
  фолбэк при отсутствии — литерал `: заголовок — автор` с нормальной пунктуацией, без `::`).
  **Нюанс:** `::` НЕ трогаем огульно — sourceType-маркеры (`Музыка::`/`Цитата::`) и авторские
  `::`-перечни остаются литеральными.
- **КАПС:** при `caps: off` — переносить прописные как есть; при `caps: on` — оживает zml1-разбор.
- **Чистка артефактов proza.ru:** последовательности ≥2 `;` (`;;`, `;;;;`, `;;; ;;;;`) — убирать
  (восстанавливать символ по контексту, иначе удалять); подлинные смайлы/глифы сохранять.
- **Label-спаны/строки СНИМАЮТСЯ конвертером (fn-ревью):** литеральная строка «Цитата» первой
  строкой `[quote]`/`[poem]` (дубль лейбла карточки, 1CM) · label-строка «Музыка под
  настроение:» перед карточкой `[mus]` (239; дубль + ловит буквицу) · заголовок-лейбл
  «ЭПИГРАФ» → `[epi]` (§2.1). Текст-содержимое при этом сохраняется полностью.
- **Музыка (fn-ревью, чистота переноса):** реф-цифру НЕ клеить к названию трека/лейблу
  («Верхом на Звезде22», «РЕКОМЕНДУЕМАЯ МУЗЫКА1») — маркер `[^N]` сохраняется ОТДЕЛЬНО рядом
  с блоком · вставкам не наследовать label чужой секции («Песнь Ступеней» 28MA) · трек —
  «Автор — Композиция» раздельными полями, глифы-артефакты `↗↑›` чистить (12F).
- **`image:` — только из РЕАЛЬНОГО `<img src>` оригинала** (как есть, в т.ч. чужой файл);
  нет картинки — поле НЕ эмитится (битые презумпции `<art>.jpg`: 12FA/12F/1CM/12L/239).

## 13. Карта реализации (render.js — единый источник истины, Node + браузер)

- **Frontmatter:** `title`, `art`, `zml`, `summary`, `date`, `image`, `editor`, `edited`, `theme`,
